# UE5 笔记写作

## 建新笔记

1. 新笔记放 `Docs/RPG/N.标题.md`。编号 = 目录中现有最大编号 + 1——动笔前先 `ls Docs/RPG` 现查，不依赖记忆或本文档里写的数字（写死必然过时）；
2. 动笔前通读**编号最大的那篇**笔记，对齐它的语感、口吻和结构惯例（如"细节与坑"小节）。已发布的笔记本身就是风格标准，比再堆规则都准；
3. 开头直入主题：不提旧工程、不提其他栏目章节、不堆文件清单；
4. 登记 `Docs/.vitepress/config.mts` 侧边栏 RPG 栏目——插在两个"查阅"条目**之前**；
5. Warrior 工程没有跳跃功能，笔记不写跳跃相关内容；
6. 发现疑似 bug：在坑/bug 专门小节标记"待改/存疑"，**不擅改用户代码**。

## 结构与文风惯例（从已发布 16 篇提炼）

通读样板笔记对齐语感之外，这些结构锚点全系列一致，照做：

1. 小节标题 = 中文序号 + 描述性标题：`## 二、GetOwningPawn<T>：static_assert + CastChecked`。标题本身要能看出这节讲什么，不写"问题""解决"这类空标题；
2. 每篇以 `## 小结` 收尾：几条要点回顾即可。**不写"下一步："展望行**——预测下一篇内容经常落空，且 VitePress 自带上/下篇导航，不需要预告；已发布笔记里的"下一步"行是历史遗留，不要模仿；
3. 开头一段（1-3 句）承接上一篇的进度线索、点明本篇要干什么。"直入主题"指不做整个系列回顾，单条进度线是应该接的（如"斧头已经背上背，持械切换的战斗逻辑不能全堆进角色类"）；
4. 核心文风：技术取舍写成"**用 X 而不是 Y + 为什么**"——每个选择都给理由，常与错误做法对照（"用 ensureMsgf 而不是 checkf 有讲究：……"）；
5. 架构/流程优先 mermaid 图；编辑器截图的识别与插入见下节「截图识别与插入」；
6. 坑与 bug 放专门小节，标题点名问题本身（如"四、真 bug：OnGiven 从未激活过"）。早期笔记的"细节与坑/常见坑"泛标题已被描述性标题取代，新笔记照新的来。

## 查阅页体系

两个查阅页收录正文里"一眼看不太懂"的东西，分工：

- `Docs/RPG/查阅-特殊语法速查.md`——**语言与宏**：模板、断言分级、反射宏要求、TSubclassOf/TSoftObjectPtr 等模板类型、前置声明、资产路径语法……
- `Docs/RPG/查阅-API速查.md`——**引擎 API**：函数怎么用、虚函数何时被调，按主题分组（Actor 与组件基础 / 移动与朝向 / 调试输出 / 标签与数据资产 / 输入管线 / 动画实例 / GAS / 武器与生成挂接）。

### 收录与链接规则（单向：笔记 → 查阅页）

1. **首次出现**的特殊语法 / UE API → 收进对应查阅页的分组；没有合适分组就新建一个，查阅页末尾的收尾句保持；
2. 笔记在**正文对应讨论位置**内联链接到查阅页（绝不在文末堆"参见"索引行）；
3. 链接文字必须**点名具体条目**（链接即查询词），如 `（Cast 两者对比见[速查](…#cast-与-castchecked)）`，不写泛泛的"涉及 API 详见"；
4. 链接一律**带小节锚点**跳到指定位置；
5. **查阅页绝不链接回笔记**——保持独立可查；两页之间只保留开头一句互相分工说明。

## 截图识别与插入

用户工作过程的截图落在 `Docs/RPG/img/`，写笔记时不能只靠文件名猜内容、更不能漏掉未安置的图：

1. **先对账**：对照 `img/` 目录和全部笔记的 `![]()` 引用，找出还没被任何笔记引用的图——这些是本篇待安置的。反向也查：笔记已引用、但 `git status` 里图片文件还未跟踪的，提醒用户图要和笔记一起提交，漏了就是死链；
2. **用 Read 看图**：逐张打开看清内容——编辑器哪个界面、蓝图哪些节点、细节面板哪项配置。插入位置和 alt 文字都依据看到的实际内容定，不依据文件名臆测；
3. **插到讨论处**：图放在正文讨论到对应内容的位置内联展示（与查阅页链接同一原则：在讨论处，不在文末堆图）；
4. **alt 与路径**：alt 用中文点名图片内容（`![GA_Hero_SpawnAxe 类默认值](img/GA_Hero_SpawnAxe.png)`）；路径中空格写 `%20`，中文文件名原样保留（`img/在骨骼中绑定武器.png`）。

## 查阅页标题必须锚点友好

标题用纯关键词，**避免 `<T>`、`_C`、`/`、`()` 等符号**——它们在 VitePress slug 里会被吞成悬空残段：

- ✅ `TSubclassOf 类引用` → 锚点 `#tsubclassof-类引用`
- ✅ `Cast 与 CastChecked` → 锚点 `#cast-与-castchecked`
- ❌ `TSubclassOf<T>：类引用` → `#tsubclassof-t-类引用`（残段）
- ❌ `资产路径两套语法：_C 后缀与 /Script/` → `#资产路径两套语法-c-后缀与-script`

VitePress 锚点由标题渲染文本生成，规则要点（加锚点前先核对）：

- NFKD 归一化：全角标点（`：（）`）折成半角后按半角规则处理；
- 空格与 `~ \` ! @ # $ % ^ & * ( ) - _ + = [ ] { } | \ ; : " ' " " ' ' < > , . ? /` → 连字符；**下划线也变连字符**（`UE_LOG` → `ue-log`、`WARRIOR_API` → `warrior-api`）；
- 连续连字符合并为一个，去首尾连字符，转小写；中文原样保留；
- 标题以数字开头时数字前加 `_`。

拿不准就用等价 JS 验证：

```js
str.normalize("NFKD").replace(/[̀-ͯ]/g,"")
  .replace(/[\u0000-\u001f]/g,"")
  .replace(/[\s~`!@#$%^&*()\-_+=[\]{}|\\;:"'“”‘’<>,.?/]+/g,"-")
  .replace(/-{2,}/g,"-").replace(/^-+|-+$/g,"")
  .replace(/^(\d)/,"_$1").toLowerCase()
```
