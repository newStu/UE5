# 斧头上背：软引用加载与 PossessedBy 接线

`DA_Hero` 填好了表，`GiveToAbilitySystemComponent` 写好了逻辑，但整个工程里没有任何一行代码调用它——启动数据还躺在内容浏览器里。本篇接上最后一根线：角色持住启动数据，PossessedBy 时同步加载并灌入 ASC，斧头真正背上背。顺带修掉一个让 `OnGiven` 能力从未自动激活的真 bug，以及蓝图侧"socket 怎么调都不生效"的资产错位坑。

## 一、持有方式：为什么是 TSoftObjectPtr

角色引用启动数据有三种写法，先看对比：

![三种引用与加载方式](img/Loading%20Methods.png)

- **硬引用（UPROPERTY 裸指针）**——角色被加载时 `DA_Hero` 跟着一起进内存。一块启动数据无所谓，但这个模式铺开到几十个角色 × 每人数张数据表，开局就是一串无差别的连锁加载；
- **构造时加载（ConstructorHelpers）**——路径写死在 C++ 里，资产改名即编译报错，配置失去了"挪进资产"的意义；
- **软引用（TSoftObjectPtr）**——编辑器里只存一条资产路径，不触发加载；什么时候要、什么时候显式 `LoadSynchronous()`。**加载时机从"引擎决定"变成"代码决定"**，这正是出生流程要的： PossessedBy 之前谁都不需要它。

```cpp
UPROPERTY(EditDefaultsOnly, BlueprintReadOnly, Category = "CharacterData")
TSoftObjectPtr<UDataAsset_StartUpDataBase> CharacterStartUpData;
```

## 二、属性落在 Base 层

`CharacterStartUpData` 没写在英雄类，而是基类 `AWarriorBaseCharacter`——敌人、Boss 将来同样有"出生配置"，槽位留在公共层，各自由蓝图默认值填各自的资产（英雄填 `DA_Hero`，敌人将来填 `DA_Enemy_xxx`）。配合 `EditDefaultsOnly`：每个角色蓝图在类默认值里选一次，实例运行期不可换——出生清单是设计期定死的东西。

同一个提交里还有一处小改动：ASC 和 AttributeSet 的 UPROPERTY 从 `EditDefaultsOnly` 改成了 `VisibleAnywhere`。这两个组件是构造函数里 `CreateDefaultSubobject` 代码创建的，`EditDefaultsOnly` 会在蓝图默认值面板里摆出一个可编辑下拉框——诱导配置的人误以为能换。`VisibleAnywhere` 只读展示，"看得见、改不了"，与"代码创建、代码持有"的事实对齐。

## 三、PossessedBy：两代接力

基类先守门：

```cpp
void AWarriorBaseCharacter::PossessedBy(AController* NewController)
{
    Super::PossessedBy(NewController);

    if (WarriorAbilitySystemComponent)
    {
        WarriorAbilitySystemComponent->InitAbilityActorInfo(this, this);

        ensureMsgf(!CharacterStartUpData.IsNull(), 
            TEXT("Forgot to assign start up to %s"), *GetName());
    }
}
```

用 `ensureMsgf` 而不是 `checkf` 有讲究：**check 系炸了进程就停，ensure 系只断言一次、进程继续，且发布版可关**。"忘配启动数据"是配置疏漏而非代码逻辑错误，编辑器里弹一次警告、报出角色名，够用了；真用 check 把游戏炸死反而过度。

英雄子类干粗活：

```cpp
void AWarriorHeroCharacter::PossessedBy(AController* NewController)
{
    Super::PossessedBy(NewController);   // 先 InitAbilityActorInfo + 守卫
    if (!CharacterStartUpData.IsNull())
    {
        if (UDataAsset_StartUpDataBase* LoadDataBase = CharacterStartUpData.LoadSynchronous())
        {
            LoadDataBase->GiveToAbilitySystemComponent(WarriorAbilitySystemComponent);
        }
    }
}
```

两处细节：

- **顺序不能倒**：`Super::PossessedBy` 里 `InitAbilityActorInfo` 先执行，ActorInfo 就位后授予的能力激活时才拿得到 AvatarActor。若先授予后初始化，GA 图表里 `Get Avatar Actor from Actor Info` 返回空，Cast 失败静默断链；
- **双重判空**：`IsNull()` 挡"蓝图里没填资产"，`LoadSynchronous()` 返回值再判一次挡"路径失效（资产被移动/删除）"——软引用的路径是字符串，编译期不校验存在性。

至此第十四篇 mermaid 里的断点闭合：PossessedBy → LoadSynchronous → GiveToAbilitySystemComponent → GrantAbilities → GiveAbility → OnGiveAbility（策略分岔）→ ActivateAbility → 斧头挂上 AxeBackSocket。

## 四、真 bug：OnGiven 从未激活过

链路接通的瞬间，一个早就埋下的 bug 现形——斧头根本不生成。`WarriorGameplayAbility.cpp` 的激活策略分岔：

```cpp
// 修复前
if (ActorInfo && Spec.IsActive())      // 永远为 false
// 修复后
if (ActorInfo && !Spec.IsActive())     // 取反漏了
{
    ActorInfo->AbilitySystemComponent->TryActivateAbility(Spec.Handle);
}
```

`Spec.IsActive()` 问的是"能力当前是否正在运行"。能力**刚被授予、还没激活过**，`IsActive()` 必然返回 false——原代码的条件永远不成立，`TryActivateAbility` 从未被调用，所有 `OnGiven` 策略的能力全部静默挂机。正确语义是"**若尚未运行，才去激活**"：`!Spec.IsActive()`。

这个 bug 的危险之处在于**静默**：不崩溃、不报错、不打印，能力授予了却永远不触发。没有断点单步或对照日志的话，只能从"效果没出现"倒推。以后凡是"授予即激活"类能力集体失灵，先查这里。

## 五、蓝图侧的坑：socket 怎么调都不生效

斧头生成了、也挂上了（走路时跟随角色、Outliner 里缩进在角色名下），但位置穿进身体里——而在骨架编辑器里把 socket 挪出几十个单位，运行时纹丝不动。排查记录留给未来自己：

1. **先确认挂接是否真的成功**：PIE 暂停 → Outliner 看武器是否缩进在角色名下 → 选中武器看 Attach Parent / Attach Socket。跟随正常 + 层级正常 = 挂接链路无问题，嫌疑转向"挂到了谁的 socket 上"；
2. **Attach 节点三个规则**（Location / Rotation / Scale）都应是 **Snap to Target**——任何一个 Keep 都会让 socket 对应维度的调整被忽略；
3. **真凶——资产错位**：角色绑定了新建的 mesh，而 socket 调在旧资产上，同名 Barbarian 模型肉眼无法区分。运行时读的是角色 SKM 引用的那份骨架，改另一份当然没反应。

防呆做法：**想调角色挂点，永远从 BP 里双击 Mesh 组件的 Skeletal Mesh Asset 引用进入编辑器**——打开的必然是角色真正使用的那份资产，从根上杜绝开错。另：武器姿势只在 socket 上调，不要在武器蓝图的根组件上旋转/缩放去"掰正"，两边会打架。

## 小结

- 启动数据用 `TSoftObjectPtr` 软引用持有：编辑器只存路径，PossessedBy 时 `LoadSynchronous()` 显式加载，加载时机归代码管；
- `CharacterStartUpData` 落基类、`EditDefaultsOnly` 定死出生清单；ASC/AttributeSet 改 `VisibleAnywhere`，代码创建的组件只读展示；
- 守卫分级：配置疏漏用 `ensureMsgf`（报角色名、只弹一次、发布版可关），逻辑错误才用 check；
- `Super::PossessedBy` 先行，ActorInfo 就位后再授予，GA 激活时才拿得到 Avatar；
- `!Spec.IsActive()` 取反修复：OnGiven 能力从"静默永不激活"恢复"授予即激活"；
- socket 不生效的排查顺序：挂接验证 → Attach 规则 → 资产是否同一份。
