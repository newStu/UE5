# 调试打印与 Debug 助手

工程骨架能跑之后，第一件要做的事是让代码"能说话"——确认一个函数到底有没有被调用、值对不对。UE 里最轻量的手段是屏幕调试消息 `AddOnScreenDebugMessage` 加输出日志 `UE_LOG`，但这两行裸写又长又啰嗦。Warrior 的做法是先花五分钟写一个 header-only 的 `Debug::Print` 助手，之后整个工程的调试打印都走它。

## 一、Debug 助手长什么样

整个助手只有一个头文件 `Public/WarriorDebugHelper.h`，没有对应 `.cpp`：

```cpp
#pragma once

namespace Debug
{
    static void Print(const FString& Message, const FColor& Color = FColor::MakeRandomColor(), int32 InKey = -1)
    {
        if (GEngine)
        {
            GEngine->AddOnScreenDebugMessage(InKey, 7.f, Color, Message);
            UE_LOG(LogTemp, Warning, TEXT("%s"), *Message);
        }
    }
}
```

调用侧只有一行：

```cpp
// Private/Character/WarriorHeroCharacter.cpp
void AWarriorHeroCharacter::BeginPlay()
{
    Super::BeginPlay();

    Debug::Print(TEXT("Hello, Working"));
}
```

几个设计点拆开看。

**namespace 而不是类**。打印是无状态的纯工具函数，没有成员变量、不需要实例化，`namespace Debug` + 自由函数是最贴切的形态。调用处写 `Debug::Print(...)`，一眼能看出这是调试代码——将来要排查或移除，全局搜 `Debug::` 就够。

**header-only + static**。函数直接实现在头文件里并标 `static`，每个 include 它的 `.cpp` 都拿到一份自己的拷贝。对普通工具这会是代码膨胀的坏味道，对调试助手无所谓——它天生就要被到处 include，省一个 `.cpp` 换"放下就能用"的顺手，划算。

**三个参数两个带默认值**。`Color` 默认 `MakeRandomColor()`——每次调用随机取色，多条消息堆在屏幕上时天然按颜色区分；`InKey` 默认 `-1`。也就是说最常用的形态就是 `Debug::Print(TEXT("..."))` 一个参数打天下，需要时再显式传参。

**`if (GEngine)` 判空**。`GEngine` 是全局引擎指针，在命令行工具（commandlet）、引擎极早期或收尾阶段可能为空。裸调 `GEngine->AddOnScreenDebugMessage(...)` 在 PIE 里没事，一旦代码被 cook 脚本或自动化测试跑到就可能崩。判空是全局指针的基本礼节。

**文件放 `Public/` 根目录**。注意 include 写的是 `#include "WarriorDebugHelper.h"`——不带目录前缀。`Public/` 本身就是 include 搜索路径，文件直接躺在 `Public/` 根下，路径自然就是裸文件名；和 `Public/Character/` 下的类要写 `"Character/xxx.h"` 是同一套规则的两面。

## 二、AddOnScreenDebugMessage 的两个关键参数

```cpp
GEngine->AddOnScreenDebugMessage(InKey, 7.f, Color, Message);
```

签名是 `(Key, TimeToDisplay, DisplayColor, DebugMessage)`。对调试体验影响最大的是 **Key**：

| Key 值 | 行为 | 适用场景 |
|---|---|---|
| `-1`（默认） | 每次调用**追加**一条新消息 | 一次性事件："进入了某函数"、"捡到了道具" |
| `≥ 0` 的固定值 | 同 Key 的旧消息被**替换**，屏幕上永远只有一条 | 持续状态：当前速度、血量、每帧刷新的检测结果 |

想在屏幕上盯一个变化的值，传固定 Key（比如 `1`），消息会原地刷新而不是刷屏；想看事件发生的顺序和次数，用默认 `-1` 让它们一条条排下来。配合默认随机色，追加模式下每条消息颜色不同，扫一眼就能分辨。

`7.f` 是消息在屏幕上的停留秒数，按需调。打印频率高于停留时长时，`-1` 模式下消息会堆叠（有上限，超出后最早的被顶掉）。

## 三、为什么包一层，而不是直接调 GEngine

裸调一次并不难，但裸调会贯穿整个工程，包一层的收益在规模上：

1. **调用侧缩短**——从 `GEngine->AddOnScreenDebugMessage(-1, 7.f, FColor::Cyan, TEXT("..."))` 缩到 `Debug::Print(TEXT("..."))`，调试打印的频率越高，这行代码被写的次数越多；
2. **格式统一**——时长、日志类别（`LogTemp`）、Verbosity 全工程一致，输出日志里筛选 `LogTemp` 就能看到所有调试输出；
3. **单点收口**——发布时想干掉全部屏幕消息，改这一个函数就行（比如加个编译开关或直接注释掉那行），几十处调用代码一行不用动。

同时打 `UE_LOG` 不是多余：屏幕消息只在有视口的游戏运行里可见，输出日志（Output Log 窗口）才是排查的主战场——带时间戳、可搜索、可复制、打包后也能看日志文件。一条 `Print` 两个出口，覆盖两种调试场景。

## 四、BeginPlay：第一个真正用上的生命周期函数

`WarriorHeroCharacter` 从空类变成有了第一个成员函数：

```cpp
// Public/Character/WarriorHeroCharacter.h
public:
    virtual void BeginPlay() override;
```

`BeginPlay` 是 Actor 生命周期里第一个值得关心的 gameplay 起点：在 Actor 生成、组件初始化完成（`PostInitializeComponents`）之后，玩法正式开始时调用一次。关卡里摆好的 Actor 在地图加载后调用，运行时 `SpawnActor` 出来的在生成流程末尾调用。"这个 Actor 开局要做的事"写在这里——它和构造函数的分工是：**构造函数管"出生时的配置"，BeginPlay 管"游戏开始时的逻辑"**。

两行各有一个容易忽略的点：

- **`Super::BeginPlay()` 必须调，且写在最前**。`AActor::BeginPlay` 的父类实现负责把 BeginPlay 派发给 Actor 身上所有组件、触发蓝图 `Event BeginPlay`。漏掉这行，角色的组件不会启动、蓝图侧的 BeginPlay 不会触发——症状隐蔽，游戏照样能跑，只是"某些东西没工作"。"重写生命周期函数先调 Super 再干活"直接当成肌肉记忆；
- **`override` 关键字照写不省**。编译器替你校验签名确实覆盖了父类的虚函数——拼写错了（比如 `Beginplay`）直接编译报错，而不是默默声明了一个新函数、然后疑惑为什么没被调用。

顺带一提 `UE_LOG` 里出现两次的 `TEXT("%s"), *Message`：`UE_LOG` 是变参宏，`FString` 传参要解引用取 `%s`，这是它的固定套路，`Debug::Print` 包一层的另一个好处就是这种样板只写一次。

## 五、常见坑

1. **漏调 `Super::BeginPlay()`**——组件不启动、蓝图 Event 不触发，且没有任何报错。重写任何生命周期函数，第一行永远是 Super；
2. **在构造函数里 `Debug::Print`**——构造阶段可能发生在 CDO（类默认对象）身上、甚至编辑器加载时，打印出来的东西和"游戏开始"对不上号。运行时逻辑放 `BeginPlay` 及之后，构造函数只做配置；
3. **盯变化值时忘传 Key**——每帧刷新的值用默认 `-1`，消息瞬间刷满屏幕还互相顶掉；固定 Key 才是"原地刷新"的用法；
4. **`static` 头文件函数想在链接期共享状态**——每个编译单元一份拷贝，函数里的 `static` 局部变量也是各自独立的。调试打印无状态所以无所谓；哪天要加计数器之类的状态，就得改成 `inline` 或挪进 `.cpp`；
5. **屏幕消息当正式 UI 用**——`AddOnScreenDebugMessage` 只在开发期有意义，打包发布后玩家同样看得到。它的定位是调试工具，正式 HUD 走 UMG。

## 小结

- `Debug::Print`：header-only 助手，`namespace Debug` + `static` 函数，`Public/` 根目录下 include 裸文件名；默认随机色、默认 Key `-1`；
- Key 语义：`-1` 追加消息记事件，固定 Key 原地替换盯状态；时长 `7.f` 可调；
- 一个函数两个出口：屏幕消息给运行中看，`UE_LOG(LogTemp)` 给输出日志搜——发布时单点收口，一行注释干掉全部屏幕打印；
- `BeginPlay` 是 gameplay 起点：构造管配置、BeginPlay 管开局逻辑；重写先调 `Super`，`override` 不省；
- `GEngine` 判空是全局指针的基本礼节，commandlet 与自动化环境里它可能为空。
