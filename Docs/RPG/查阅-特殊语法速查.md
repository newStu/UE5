# 查阅：特殊语法速查

与[《查阅：API 速查》](查阅-API速查.md)的分工：那边管**引擎 API**（函数怎么用、虚函数何时被调），这边管**语言与宏**（模板怎么写、断言怎么分级、反射宏什么要求）。每条给三样东西：它是什么、引擎为什么这么写、本工程用在哪。正文笔记只记设计取舍，语法细节看这里。

## #pragma once 与 #pragma region

```cpp
#pragma once

#pragma region Components
/* ...组件 UPROPERTY... */
#pragma endregion
```

- **`#pragma once`**：头文件防重复包含的预处理指令——同一个翻译单元里第二次 include 该文件时整份跳过。与传统的 `#ifndef/#define/#endif` include guard 等效，但不用发明宏名、不会宏名撞车，UE 工程一律用它；
- **`#pragma region 名字` / `#pragma endregion`**：纯 IDE 折叠用的预处理指令，编译器忽略之，只服务编辑器。把"这个类有哪些组件"框成可折叠区块，类变大后组件、属性、函数各一个 region，导航成本立降。

## 反射宏家族：UCLASS / USTRUCT / UENUM / GENERATED_BODY

```cpp
UCLASS()
class WARRIOR_API AWarriorWeaponBase : public AActor
{
    GENERATED_BODY()
    /* ... */
};

USTRUCT(BlueprintType)
struct FWarriorInputActionConfig
{
    GENERATED_BODY()
    /* ... */
};

UENUM(BlueprintType)
enum class EWarriorAbilityActivationPolicy : uint8 {
    OnTriggered,
    OnGiven
};
```

- UE 的类想进反射系统（蓝图可见、可序列化、可被 GC 追踪），必须**类声明前挂宏 + 类体内第一段写 `GENERATED_BODY()`**——后者是 UHT（Unreal Header Tool，头文件预编译 pass）注入生成代码的位置，漏写直接编译报错；
- `USTRUCT` 同样要 `GENERATED_BODY()`；`BlueprintType` 让蓝图能声明、读写这个结构类型的变量；
- `UENUM` 要进蓝图下拉框，两个条件缺一不可：**`enum class` + 底层类型 `uint8`**（反射与网络序列化的要求），外加 `BlueprintType`。忘了 BlueprintType 的症状是蓝图 Details 面板看不到这个枚举；
- 改这些宏属于 UHT 层面的变更，需要完整重编译，不是普通代码热重载能吃下的。

## UPROPERTY 暴露档位与 meta

```cpp
UPROPERTY(VisibleAnywhere, BlueprintReadOnly, Category = "Camera", meta = (AllowPrivateAccess = "true"))
USpringArmComponent* CameraBoom;

UPROPERTY(EditDefaultsOnly, BlueprintReadOnly, meta=(Categories = "InputTag"))
FGameplayTag InputTag;

UPROPERTY(EditDefaultsOnly, BlueprintReadOnly, meta=(TitleProperty="InputTag"))
TArray<FWarriorInputActionConfig> NativeInputActions;
```

暴露档位是**两个维度的组合**——"可编辑还是只可见" × "哪里能改/看"：

| | **Anywhere**（实例 + 默认值） | **DefaultsOnly**（仅类默认值） |
|---|---|---|
| **Edit**（可改） | `EditAnywhere` | `EditDefaultsOnly` |
| **Visible**（只读） | `VisibleAnywhere` | `VisibleDefaultsOnly` |

- 代码创建的组件给 `VisibleAnywhere`——"看得见、改不了"，不在蓝图面板摆可编辑下拉框诱导误配；设计参数（如 Relax 阈值）给 `EditDefaultsOnly`——子类默认值可调、实例不可动，值来源单一；
- **`AllowPrivateAccess = "true"`**：反射系统默认拒绝暴露 private 成员，这条 meta 是例外通道——没有它，`BlueprintReadOnly` 对 private 成员直接编译报错；
- **`meta=(Categories = "InputTag")`**：标签选择下拉框只显示该父级下的标签，配错在编辑期挡住；
- **`meta=(TitleProperty="成员名")`**：数组每行的折叠标题显示该成员的值（而不是 0/1/2 下标），扫一眼就知道哪行是哪个输入。

## 前置声明：class UHeroCombatComponent;

- 头文件里一句 `class UHeroCombatComponent;` 告诉编译器"存在这么个类"，之后**指针和引用**可以先声明着用，完整定义延迟到 cpp 里 `#include`；
- 价值是切断 include 传染：被前置声明的类的头文件改动，不再连锁重编译所有包含本头文件的 cpp；也是解头文件**循环包含**的标准手段；
- 限制：前置声明的类型只能出现在指针/引用位置；继承、`new`、调成员、`sizeof` 都需要完整定义，必须留在 cpp；
- 易错点：前置声明的类名必须带 `U`/`A` 前缀且一字不差——写成 `class SpringArmComponent;` 合法但声明的是一个无关新类，什么也没前置。

## 资产路径两套语法

```ini
GlobalDefaultGameMode=/Game/GameModes/BP_BaseGameMode.BP_BaseGameMode_C
DefaultInputComponentClass=/Script/Warrior.WarriorInputComponent
```

- **引用蓝图类必须带 `_C` 后缀**（Class 的 C）：`BP_BaseGameMode.BP_BaseGameMode_C` 指向蓝图**生成的类**，不带 `_C` 指向的是资产实例——ini 里漏了直接路径解析失败；
- **引用 C++ 类用 `/Script/` + 模块名 + 类名**：`/Script/Warrior.WarriorInputComponent`；
- 两套规则分别对应"蓝图世界"和"原生世界"，GameMode 默认类、InputComponent 换装这些 ini/Project Settings 配置里天天要用。

## TEXT() 与 UE_LOG 的变参套路

```cpp
UE_LOG(LogTemp, Warning, TEXT("%s"), *Message);
Debug::Print(TEXT("Hello, Working"));
```

- **`TEXT("...")`**：把字符串字面量包成 `TCHAR` 宽字符——UE 跨平台字符串的统一入口，中文、路径、格式化串一律裹它；
- **`UE_LOG` 的 `%s` 传 `FString` 必须解引用**：`TEXT("%s"), *Message`——`*` 取出内部的 `TCHAR*` C 串。固定套路，忘 `*` 编译报错或打出乱码；
- `UE_LOG(类别, 级别, 格式, ...)` 是变参宏：类别用于输出日志里筛选（工程调试统一走 `LogTemp`），级别常用 `Warning`/`Display`/`Error`。

## header-only 的 static 自由函数

```cpp
// WarriorDebugHelper.h —— 只有 .h 没有 .cpp
namespace Debug
{
    static void Print(const FString& Message, ...) { /* ... */ }
}
```

- 函数直接实现在头文件里并标 `static`：每个 include 它的 `.cpp` 拿到**一份自己的拷贝**（internal linkage）；
- 普通工具这是代码膨胀的坏味道，调试助手无所谓——天生要被到处 include，省一个 `.cpp` 换"放下就能用"；
- 陷阱：各拷贝互相独立，函数内的 `static` 局部变量也是各算各的——想跨编译单元共享状态就得改 `inline` 或挪 `.cpp`。

## WARRIOR_API：模块导出宏

```cpp
namespace WarriorGameplayTags
{
    WARRIOR_API UE_DECLARE_GAMEPLAY_TAG_EXTERN(InputTag_Move);
}
```

- 展开为平台的 DLL 导出符号（`__declspec(dllexport)` 一族）：本模块的**代码符号**对其他模块可见；
- 不加它：本模块内编译正常，其他模块一引用就 `unresolved external symbol`——"单一模块里能跑"和"工程级可用"的区别；
- 只在符号要跨模块时需要；游戏模块内部的私有类可以不导出。

## Native Gameplay Tags 宏对

```cpp
// .h —— 声明
WARRIOR_API UE_DECLARE_GAMEPLAY_TAG_EXTERN(InputTag_Move);
// .cpp —— 定义 + 注册
UE_DEFINE_GAMEPLAY_TAG(InputTag_Move, "InputTag.Move");
```

- 一对宏两处出现，与"函数声明在 .h、定义在 .cpp"同构：EXTERN 版声明"存在这个 `FGameplayTag` 常量"，DEFINE 版真正定义并在**程序启动时注册进全局标签表**；
- 引用侧 `WarriorGameplayTags::InputTag_Move` 拿到的是常量对象——变量名拼错**编译期**报错，这是相对字符串的最大优势；
- 成对纪律：声明了忘定义（链接错）、定义了忘声明（别处用不了）、变量名与标签字符串不一致（编译照过、运行时表里是错的字符串，靠命名约定 `InputTag_Move` ↔ `"InputTag.Move"` 肉眼对账）。

## 断言家族：check / checkf / ensure / ensureMsgf

| 宏 | 行为 | 适用 |
|---|---|---|
| `check(x)` | 假则崩，不带说明 | "失败了也无话可说"（如子系统必然存在） |
| `checkf(x, TEXT("..."))` | 崩时带一句人话 | 指认锅主："哪个资产忘配了" |
| `ensureMsgf(x, TEXT("..."))` | 断言一次、**可继续跑**，发布版可关 | 配置疏漏类：报角色名但不炸死游戏 |
| `ensureAlways` | 每次触发都断 | 同上，且要统计频次 |

- 分级判据：**代码不变量用 check 系**（写错了越早炸越好），**配置/数据疏漏用 ensure 系**（人的锅，报警继续）——`ensureMsgf` 守卫启动数据是教科书案例；
- check 系是**开发期断言**：`DO_CHECK=0` 的发布构建里整条表达式被编译掉——所以**断言里绝不放带副作用的调用**（函数调用、赋值），它们在发布版里凭空消失；
- ensure 系的表达式在任何构建里都会求值，适合"可恢复的异常"。

## Cast 与 CastChecked

- UE 自己的转型函数，走反射系统的类层级（IsA 链），只能转 UCLASS 体系内的指针——原生类型、非 UObject 类不接待；
- `Cast<T>`：失败返回 `nullptr`——用于"**可能**转不过去"且失败合法的场景（如 ABP 被美术拿到别的角色上测试），调用方判空跳过；
- `CastChecked<T>`：失败断言崩溃——用于"逻辑上**必然**成功"的不变量（如 ini 已全局换装 `WarriorInputComponent`，转型失败只可能是配置漏改，当场炸好过静默空指针）；Shipping 默认剔除断言、退化为直接转型，不带运行时开销；
- 与原生 `dynamic_cast` 的关系：dynamic_cast 依赖 RTTI，UE 工程常关 RTTI 不可用；`Cast` 是引擎自建等价物，失败语义明确。

## 模板成员函数

```cpp
template<class UserObject, typename CallbackFunc>
void BindNativeInputAction(..., UserObject* ContextObject, CallbackFunc Func);
```

- `template<class T>` 与 `template<typename T>` **完全等价**，UE 源码惯用 `class`；可以多参数（如"对象 + 成员函数"两参数）；
- **调用处才决定 T**：`InputActionValue.Get<FVector2D>()`、`GetOwningPawn<AWarriorHeroCharacter>()`，每种 T 实例化一份；
- **模板定义必须放头文件**：模板是编译期配方，只有被调用时才实例化——定义放 `.cpp` 的话其他翻译单元链接时 `unresolved external symbol`。这条与普通成员函数"声明 .h 定义 .cpp"的惯例正好相反；
- UHT 限制：`UFUNCTION()` / `UPROPERTY()` 不能作用于模板——模板成员天然是纯 C++ 内部通道，蓝图不可见。

## 模板重载与非模板重载并存

```cpp
template<class T>
T* GetOwningPawn() const { /* ... */ }

APawn* GetOwningPawn() const
{
    return GetOwningPawn<APawn>();
}
```

- 同名两个函数：写尖括号走模板版，不写走非模板重载——重载决议时非模板的精确匹配优先；
- 引擎源码常见手法：最常用的类型给个免模板参数的快捷入口，`APawn::GetController<T>()` 与 `GetController()` 就是同款布局（`GetOwningController<APlayerController>()` 一步取值 + 转型）。

## ThisClass：本类别名

```cpp
WarriorInputComponent->BindNativeInputAction(..., this, &ThisClass::Input_Move);
```

- `ThisClass` 是 UE 类体系里预生成的"本类"类型别名（等价 `using ThisClass = AWarriorHeroCharacter;`）；
- 写 `&ThisClass::Input_Move` 比抄完整类名不怕拼错，类改名时引用跟着自动正确；
- 同族亲戚：`Super`（直接父类的别名，`Super::BeginPlay()` 就是它在干活）——两个都是 UE 在生成代码里塞进每个类的便利名字。

## UE 接口：I 前缀与多继承

```cpp
class WARRIOR_API AWarriorBaseCharacter : public ACharacter, public IAbilitySystemInterface
{
public:
    virtual UAbilitySystemComponent* GetAbilitySystemComponent() const override;
};
```

- UE 的接口类以 `I` 开头（`IAbilitySystemInterface`…），成员全是纯虚函数，**没有状态**；
- UObject 体系的多重继承只允许这一种形态：**一个正常基类 + 任意多个接口**——接口无状态所以不参与菱形继承的麻烦；
- 实现 = 多继承接口 + `override` 它的虚函数。价值是"标准问法"：任何外部系统拿到 Actor 都能 `GetAbilitySystemComponent()` 统一索要 ASC，不必知道它内部哪个成员存着组件；
- 引擎侧约定（`GetAbilitySystemComponentFromActor` 这类通用函数）就靠这个接口找到 ASC——不实现它，通用获取函数空手而归。

## TWeakObjectPtr 弱引用

- 持有对象指针但**不阻止 GC 回收**——对象被销毁时弱引用自动失效，不会悬垂，但也可能随时变空；
- `FGameplayAbilityActorInfo` 里的 `AbilitySystemComponent` 就是弱引用，规矩：**先 `IsValid()` 再 `->`**，或取一次 `.Get()` 存局部变量用到底；
- 与裸指针对比：裸指针 GC 不认识、对象销毁后悬垂（崩在十万八千里外）；与 `UPROPERTY` 强引用对比：强引用会钉住对象不让回收。弱引用是"我认识它，但不留它"的中立姿态。

## FORCEINLINE

- UE 宏，展开为各编译器的**强制内联**（MSVC `__forceinline`、GCC/Clang `always_inline`）——普通 `inline` 是"建议"，这个是"命令"；
- 用在短小、热路径的 getter：一行返回成员指针的函数，调用开销比函数体还大，内联后为零成本访问（`GetWeaponCollisionBox()`、`GetHeroCombatComponent()`）；
- 代价是滥用会二进制膨胀、编译变慢——一两行的访问器是最甜的使用区。

## TSubclassOf 类引用

```cpp
UPROPERTY(EditDefaultsOnly, Category = "StartUpData")
TArray<TSubclassOf<UWarriorGameplayAbility>> ActiveOnGivenAbilities;
```

- 装的是**类**（`UClass`）而不是实例——"生成什么"在生成之前只需要类，`SpawnActor` 的 Class 引脚、能力清单数组都是它；
- 比裸 `UClass*` 强在**类型约束**：编辑器下拉只列 `T` 及其子类，拖错类直接拒绝；C++ 侧 `Cast` 到具体类型也免了；
- GA 蓝图里的 `Weapon Class to Spawn` 变量就是 `TSubclassOf<AWarriorWeaponBase>`——父蓝图留空、子蓝图填值，"共享逻辑、差异化数据"的口子。

## TSoftObjectPtr 软引用

```cpp
UPROPERTY(EditDefaultsOnly, BlueprintReadOnly, Category = "CharacterData")
TSoftObjectPtr<UDataAsset_StartUpDataBase> CharacterStartUpData;

if (UDataAsset_StartUpDataBase* Loaded = CharacterStartUpData.LoadSynchronous())
{
    Loaded->GiveToAbilitySystemComponent(WarriorAbilitySystemComponent);
}
```

- 编辑器里只存**一条资产路径**，不触发加载——硬引用（裸 `UPROPERTY` 指针）会让资产跟着持有者一起进内存，软引用把**加载时机从"引擎决定"变成"代码决定"**；
- `LoadSynchronous()` 显式同步加载并返回裸指针；
- 双重判空：`IsNull()` 挡"蓝图里没填资产"，`LoadSynchronous()` 返回值再判一次挡"路径失效（资产被移动/删除）"——软引用的路径是字符串，编译期不校验存在性。

## static_assert 与类型 trait

```cpp
static_assert(TPointerIsConvertibleFromTo<T,APawn>::Value,
    "'T' Template Parameter get GetPawn must be derived from APawn");
return CastChecked<T>(GetOwner());
```

- **`static_assert`**：**编译期**断言——条件不成立直接编译失败，报错内容就是第二个参数的字符串。普通断言（check/ensure）跑到那行才检查，这个连程序都不用跑；零运行时成本；
- **`TPointerIsConvertibleFromTo<From, To>::Value`**：UE 的类型 trait（type trait），编译期判断 `From*` 能否隐式转换为 `To*`，答案从 `::Value` 读——"trait 结构体是标签，答案在 Value"是 UE/STL trait 体系的通用惯例；
- 组合起来 = 模板约束："T 必须是 APawn 派生类，否则不许编译"。模板参数什么类型都能传，与其等运行时炸出被转换链污染的含糊错误，不如编译期挡死、报自定义信息。
