# 混合空间与移动状态机（Idle ↔ Jog）

上一篇把 `GroundSpeed` 与 `bHasAcceleration` 逐帧喂进了 AnimInstance，本篇在蓝图侧消费它们：建一维混合空间 `BS_UnarmedLocomotion` 按速度连续混合站立与慢跑，在 `ABP_Hero` 的 AnimGraph 里搭 Idle ↔ Jog 两状态状态机管离散切换，最后把 Anim Class 指认到角色身上——角色从 T-Pose 里活过来。核心分工一句话：**混合空间管"连续"（速度 0 → 满速的无级过渡），状态机管"离散"（动/停两个明确的姿态档位）**，两者不是二选一，而是嵌套着用。

## 一、链路全景

```
BP_HeroCharacter (SkeletalMeshComponent)
   │  Anim Class = ABP_Hero
   ▼
ABP_Hero : AnimGraph
   └─ 状态机 UnarmedLocomotion
        ├─ Idle ── Hero_Unarmed_Idle        (Sequence Player)
        └─ Jog  ── BS_UnarmedLocomotion     (Blend Space Player, X = GroundSpeed)
        过渡：Idle → Jog / Jog → Idle（双向）
   ▲
   │ GroundSpeed / bHasAcceleration (BlueprintReadOnly)
WarriorCharacterAnimInstance（上一篇的 NativeUpdateAnimation）
```

三份新资产/改动各就各位：混合空间放 `PlayerCharacter/AnimBP/BlendSpace/`，动画蓝图是 `PlayerCharacter/AnimBP/ABP_Hero`，角色蓝图只改一处 Anim Class 指认。

## 二、BS_UnarmedLocomotion：一维混合空间

创建：内容浏览器 → Animation → **Blend Space 1D**，骨架选 `SK_Hero`——与角色 mesh 同一副骨架是硬前提，BS、ABP、mesh 三者任何一环骨架错位，资产就互相引用不上。

配置只有三件事：

1. **轴命名 `GroundSpeed`**——和 C++ 侧暴露的变量同名，接引脚时一眼对上；
2. **轴范围 0 → 盖过最大移动速度**——上限小于实际速度就永远够不到满速姿态；上限远超则低速段姿态挤在轴的一头；
3. **摆两个动画**——`Hero_Unarmed_Idle` 拖到 0 端，`Hero_Unarmed_Jog_Fwd` 拖到满速端。网格上两点之间引擎自动插值：速度 200 时就是"半蹲半跑"的中间姿态，不需要手工配任何过渡。

为什么选 **1D** 而不是普通混合空间：普通 Blend Space 是二维网格（典型如"速度 × 方向"九宫格 locomotion），1D 只有一根轴。当前姿态只有一个自由度——跑多快，用 1D 恰好；将来要方向混合再升级成二维，不浪费现在的配置。

> 预览技巧：编辑器里按住 **Ctrl + 拖动轴滑块**，实时看任意速度下的混合姿态，调轴范围时先这么扫一遍。

## 三、ABP_Hero：UnarmedLocomotion 状态机

AnimGraph 里右键 → New State Machine，命名 `UnarmedLocomotion`——名字里的 Unarmed 是给将来留的位：持斧（Axe）后会有第二套持械 locomotion，届时按武装状态选状态机，命名现在就分好家。

状态机内部双击进入，`Entry → Idle ↔ Jog` 双向连线，两个状态各挂一个播放器：

- **Idle 状态：Sequence Player** 播 `Hero_Unarmed_Idle`——静止就一个动画，序列播放器足矣；
- **Jog 状态：Blend Space Player** 采 `BS_UnarmedLocomotion`，**X 引脚接 C++ 侧的 `GroundSpeed`**——Jog 内部仍是无级混合，速度爬升时从走滑向跑。

过渡规则（双击状态间的连线写条件）是这一节真正的主菜，两个方向判据不同：

- **Idle → Jog 看 `bHasAcceleration`**——有输入加速度就切，起跑零延迟。若改用"速度超过阈值"判，按键后要等半拍速度起来才切，手感发闷；
- **Jog → Idle 看 `GroundSpeed` 回落**——松手后角色滑行一小段，这期间速度在衰减，Jog 状态内的混合空间顺带把姿态从慢跑滑向站立，等速度真正归零才交回 Idle。起跑与刹车两种"中间态"就这样分开处理——这正是上一篇坚持**同时**喂两个变量的原因：单看速度，"正在加速"和"正在滑行"是分不清的。

> 状态机多状态实战（Locomotion / 起跳 / 空中 / 落地四状态 + 过渡规则调参）在蓝图栏目[《角色跳跃》](../蓝图/4.角色跳跃/角色跳跃.md)有整篇展开，混合空间的轴配置基础在[《动画创建》](../蓝图/2.动画创建/动画创建.md)。

另外注意过渡自带的 **crossfade 混合时间**（默认 0.2s 上下）：状态切换不是硬切，前一个姿态淡出、后一个淡入，连线上的小图标可以单独调每个过渡的混合时长与惯性混合（Inertialization）选项。

## 四、指认到角色

蓝图侧只剩机械一步：`BP_HeroCharacter` 的 SkeletalMeshComponent → Animation → **Anim Class 指到 `ABP_Hero`**。ABP 的 Parent Class 上一篇已 Reparent 成 `WarriorHeroAnimInstance`，两站指认就此补齐，链条闭合——运行时引擎按 Anim Class 实例化 AnimInstance，C++ 逐帧刷的两个变量顺着继承流进状态机的过渡条件和混合空间的轴。

PIE 验证三拍：静止站立不抖、按住移动进入慢跑且速度爬升姿态渐变、松手滑行减速自然回落站立。

## 五、细节与坑

1. **过渡条件用错变量**——双向都拿 `GroundSpeed` 判是最常见的偷懒：起跑有延迟（等速度过阈值）、刹车瞬间回 Idle（滑行段姿态僵在站立）。记住配对的语义：**加速度判"想不想动"，速度判"动没动"**；
2. **骨架三者不一致**——BS、ABP、角色 mesh 必须同一 Skeleton；症状是资产创建时就选不上/引用为空，不是运行时才炸；
3. **混合空间轴范围失配**——上限低于最大移速永远到不了满速动画；远超则有效姿态挤在轴一端，插值分辨率被浪费。摆完动画 Ctrl 拖轴扫一遍再收工；
4. **AnimGraph 引用变量走的是 Fast Path**——C++ 暴露的 `BlueprintReadOnly` 变量被状态机/混合空间节点直接引用时，编译期生成属性拷贝记录（property access），**不走蓝图虚拟机**。这也是"数据在 C++ 刷、AnimGraph 直接引"比"事件图表里 get 一次"更优的机制层面的原因；
5. **状态机不是必须的**——BS 单独直连 Output Pose 也能跑（速度混合本身就能覆盖动停切换），但一旦姿态需要"档位"语义——持械、受击这类互斥、各有进出条件的新姿态——状态机 + 过渡规则比在一张混合空间里堆权重清晰得多。两状态是最小的起点，结构是给扩展准备的。

## 小结

- 三步落地：**BS_UnarmedLocomotion**（1D，轴 `GroundSpeed`，Idle 在 0 端、Jog_Fwd 在满速端）→ **ABP_Hero 里 UnarmedLocomotion 状态机**（Idle 挂序列播放器，Jog 挂混合空间播放器且 X 接 `GroundSpeed`）→ **BP_HeroCharacter 的 Anim Class 指认 ABP_Hero**；
- 过渡规则双向异判：Idle → Jog 看 `bHasAcceleration`（起跑零延迟），Jog → Idle 等 `GroundSpeed` 归零（滑行段由 Jog 内的混合空间平滑收尾）——"加速度判意图、速度判结果"；
- 混合空间与状态机是嵌套关系而非替代：前者管一个档位内的连续混合，后者管档位间的离散切换与 crossfade；
- AnimGraph 引用 C++ 变量走 property access 快速路径，无蓝图虚拟机开销。
