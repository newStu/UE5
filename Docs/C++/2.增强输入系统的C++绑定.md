# 增强输入系统（Enhanced Input）的 C++ 绑定

蓝图第 1 章里，我们在角色蓝图的事件图表中用节点绑定了 **输入映射上下文 (IMC)** 和 **输入操作 (IA)**。本节把同样的流程搬进 C++，代码来自 `MyThirdCharacter.h / .cpp`。

先明确哪些东西在哪一层做：

| 层 | 内容 | 在哪做 |
|---|---|---|
| 资产层 | IA（输入操作）、IMC（输入映射上下文）资产 | 编辑器里创建和配置，C++ / 蓝图都只是"引用"它们 |
| 逻辑层 | 绑定 IMC、绑定 IA 触发时的响应函数 | C++（本节）或蓝图事件图表 |

也就是说 **IA / IMC 资产本身和蓝图版完全一样**（`IA_Move`、`IA_Look`、`IA_Jump`、`IMC_Default`），区别只在绑定代码。

---

## 第一步：头文件里声明资产引用和响应函数

`MyThirdCharacter.h`：

```cpp
class UInputMappingContext;   // 前置声明，避免头文件里堆 include
class UInputAction;
struct FInputActionValue;

UCLASS(config=Game)
class AMyThirdCharacter : public ACharacter
{
    GENERATED_BODY()

    /** MappingContext */
    UPROPERTY(EditAnywhere, BlueprintReadOnly, Category = Input, meta = (AllowPrivateAccess = "true"))
    TObjectPtr<UInputMappingContext> DefaultMappingContext;

    /** Jump Input Action */
    UPROPERTY(EditAnywhere, BlueprintReadOnly, Category = Input, meta = (AllowPrivateAccess = "true"))
    TObjectPtr<UInputAction> JumpAction;

    /** Move Input Action */
    UPROPERTY(EditAnywhere, BlueprintReadOnly, Category = Input, meta = (AllowPrivateAccess = "true"))
    TObjectPtr<UInputAction> MoveAction;

    /** Look Input Action */
    UPROPERTY(EditAnywhere, BlueprintReadOnly, Category = Input, meta = (AllowPrivateAccess = "true"))
    TObjectPtr<UInputAction> LookAction;

protected:
    /** Called for movement input */
    void Move(const FInputActionValue& Value);

    /** Called for looking input */
    void Look(const FInputActionValue& Value);

    virtual void SetupPlayerInputComponent(class UInputComponent* PlayerInputComponent) override;
};
```

要点：

- 资产引用做成 `UPROPERTY(EditAnywhere)`，就可以**在角色蓝图子类（`BP_ThirdPersonCharacter`）的细节面板里把 IA / IMC 资产拖进去**——C++ 不写死资源路径，和 GameMode 章的原则一致；
- `Move` / `Look` 就是蓝图版"绑定输入操作"事件（`OnMove` / `OnLook`）的 C++ 形态：**普通成员函数**，不需要任何宏就能当回调；
- `TObjectPtr<T>` 是 UE5 推荐的指针写法，编辑器下带访问追踪，效果等同裸指针。

> 模板生成的这些成员是 `private` 的，所以每个 `UPROPERTY` 都带 `meta = (AllowPrivateAccess = "true")`——private 成员暴露给蓝图/编辑器时的必备标记（原因见 [常用宏与反射](/C++/4.常用宏与反射.html)）。

## 第二步：在 SetupPlayerInputComponent 里绑定

蓝图版把绑定逻辑放在 Event BeginPlay 后面；C++ 版的标准位置是 **`SetupPlayerInputComponent`**——Pawn 初始化输入时引擎自动调用它，时机比 BeginPlay 更早、更正确。

```cpp
void AMyThirdCharacter::SetupPlayerInputComponent(UInputComponent* PlayerInputComponent)
{
    // ① 添加输入映射上下文（对应蓝图的 Add Mapping Context 节点）
    if (APlayerController* PlayerController = Cast<APlayerController>(GetController()))
    {
        if (UEnhancedInputLocalPlayerSubsystem* Subsystem =
                ULocalPlayer::GetSubsystem<UEnhancedInputLocalPlayerSubsystem>(PlayerController->GetLocalPlayer()))
        {
            Subsystem->AddMappingContext(DefaultMappingContext, 0);
        }
    }

    // ② 绑定输入操作（对应蓝图的 EnhancedInputAction 事件节点）
    if (UEnhancedInputComponent* EnhancedInputComponent = Cast<UEnhancedInputComponent>(PlayerInputComponent))
    {
        // 跳跃：按下开始跳，松开停止
        EnhancedInputComponent->BindAction(JumpAction, ETriggerEvent::Started, this, &ACharacter::Jump);
        EnhancedInputComponent->BindAction(JumpAction, ETriggerEvent::Completed, this, &ACharacter::StopJumping);

        // 移动 / 视角：持续触发
        EnhancedInputComponent->BindAction(MoveAction, ETriggerEvent::Triggered, this, &AMyThirdCharacter::Move);
        EnhancedInputComponent->BindAction(LookAction, ETriggerEvent::Triggered, this, &AMyThirdCharacter::Look);
    }
}
```

### ① AddMappingContext —— 挂上按键表

IMC 是"按键 → 输入操作"的映射表，必须先注册到 **本地玩家子系统** 才生效。获取链路固定三步：

```
GetController() → PlayerController → GetLocalPlayer() → GetSubsystem<UEnhancedInputLocalPlayerSubsystem>()
```

第二个参数 `0` 是优先级，多个 IMC 同时存在时高优先级覆盖低优先级。

### ② BindAction —— 按键触发时调哪个函数

```cpp
BindAction(输入操作资产, 触发时机, 响应者, 函数指针)
```

`ETriggerEvent` 是关键，对应蓝图 IA 事件上的触发器选项：

| ETriggerEvent | 含义 | 典型用途 |
|---|---|---|
| `Started` | 刚按下 | 跳跃、开火 |
| `Triggered` | 持续触发中（按 IA 里配置的频率） | 移动、视角 |
| `Completed` | 松开 / 触发结束 | 停止跳跃、松开瞄准 |
| `Canceled` | 被取消 | 少用 |

注意 `&ACharacter::Jump` 绑的是**父类自带**函数——UE 的很多内建功能（Jump / StopJumping / AddMovementInput）不需要重写就能直接当回调。

## 第三步：实现 Move / Look

```cpp
void AMyThirdCharacter::Move(const FInputActionValue& Value)
{
    // 输入是 Vector2D（对应 IA_Move 里 Value Type = Axis2D）
    FVector2D MovementVector = Value.Get<FVector2D>();

    if (Controller != nullptr)
    {
        // 取控制器朝向，只留 Yaw（去掉俯仰，保证平面移动）
        const FRotator Rotation = Controller->GetControlRotation();
        const FRotator YawRotation(0, Rotation.Yaw, 0);

        // 由朝向算出"前"和"右"方向向量
        const FVector ForwardDirection = FRotationMatrix(YawRotation).GetUnitAxis(EAxis::X);
        const FVector RightDirection   = FRotationMatrix(YawRotation).GetUnitAxis(EAxis::Y);

        // 沿两个方向施加移动输入（Y 是前后，X 是左右）
        AddMovementInput(ForwardDirection, MovementVector.Y);
        AddMovementInput(RightDirection, MovementVector.X);
    }
}

void AMyThirdCharacter::Look(const FInputActionValue& Value)
{
    FVector2D LookAxisVector = Value.Get<FVector2D>();

    if (Controller != nullptr)
    {
        AddControllerYawInput(LookAxisVector.X);    // 左右转头
        AddControllerPitchInput(LookAxisVector.Y); // 上下俯仰
    }
}
```

对照蓝图版的"获取用户速度/方向"逻辑：

- 蓝图里 `Get Control Rotation` + `Get Forward Vector` 的组合，这里是 `FRotationMatrix(YawRotation).GetUnitAxis(EAxis::X/Y)`——数学上同一件事（旋转矩阵取单位轴向量）；
- 蓝图里的 `Add Movement Input` 节点，就是 `AddMovementInput()` 函数；
- 实际的位移由 `CharacterMovementComponent` 完成：`AddMovementInput` 只是累积输入，组件每帧按 `MaxWalkSpeed` 等参数消费它。这就是为什么构造函数里调的那堆移动参数会生效。

> **为什么要拆出 YawRotation？** 控制器旋转带俯仰（Pitch）。如果直接用完整旋转取前向量，低头时会往斜下方走。把 Pitch/Roll 清零后，移动方向始终水平——第三人称标准写法。

## 常见问题排查

| 症状 | 检查 |
|---|---|
| 完全没反应 | IMC 有没有 Add 成功（子系统获取链路里 Controller 可能还是 null，可挪到 BeginPlay 再试） |
| 个别按键没反应 | 蓝图子类细节面板里 IA / IMC 引用是不是忘了拖 |
| 响应函数不触发 | `BindAction` 用的 `ETriggerEvent` 和 IA 资产里的触发器配置是否匹配 |
| 编译报错找不到类型 | `.cpp` 里补 `#include "EnhancedInputComponent.h"`、`"EnhancedInputSubsystems.h"`、`"InputActionValue.h"` |

> 模板把 AddMappingContext 放在 SetupPlayerInputComponent 里，此时 Controller 一般已就绪；若自己改代码后发现获取不到 PlayerController，可参考社区常见做法挪到 `BeginPlay` / `Possess` 时机再挂 IMC。

---

## 小结

- IA / IMC 资产仍在编辑器建，C++ 里只放 `UPROPERTY(EditAnywhere)` 引用，由蓝图子类拖资产；
- 绑定 IMC：`UEnhancedInputLocalPlayerSubsystem::AddMappingContext`；
- 绑定 IA：`BindAction(资产, ETriggerEvent, this, 函数指针)`，触发时机按需选 Started / Triggered / Completed；
- 移动响应 = 控制器 Yaw → 前右方向向量 → `AddMovementInput`，实际位移交给 CharacterMovementComponent；
- 下一章：[组件编写与生命周期](/C++/3.组件编写与生命周期.html)。
