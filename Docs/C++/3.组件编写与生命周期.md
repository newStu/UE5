# 组件编写与生命周期

蓝图第 3 章里我们给角色"添加弹簧臂和相机组件"，第 5 章的机关（滚木、旋转指针）也全是"Actor + 组件"的组合。本节讲 C++ 视角的组件：怎么创建、怎么写一个自己的组件、Actor 和组件各自的生命周期顺序。

---

## 组件三大基类

| 基类 | 有变换（位置/旋转/缩放）？ | 典型例子 |
|---|---|---|
| `UActorComponent` | ❌ | `UCharacterMovementComponent`、自己写的功能组件 |
| `USceneComponent` | ✅，可挂接成树 | `USpringArmComponent`、音频组件 |
| `UPrimitiveComponent` | ✅，有碰撞/渲染 | `USkeletalMeshComponent`、静态网格体、胶囊体 |

规则：**需要"摆在哪里"就继承 Scene 系，纯逻辑组件继承 UActorComponent**。Scene 组件可以互相 `SetupAttachment` 形成层级（相机挂在弹簧臂末端就是一棵组件树）。

> Character 自带一棵现成的组件树：`CapsuleComponent`（根）→ `Mesh`、`CharacterMovementComponent`，模板再往上挂 `CameraBoom` → `FollowCamera`。用 `GetCapsuleComponent()` / `GetCharacterMovement()` 随时能拿到。

## 在 Actor 里创建组件

模板 `MyThirdCharacter.cpp` 构造函数里的标准写法：

```cpp
CameraBoom = CreateDefaultSubobject<USpringArmComponent>(TEXT("CameraBoom"));
CameraBoom->SetupAttachment(RootComponent);          // 挂到根组件（胶囊体）上
CameraBoom->TargetArmLength = 400.0f;                // 臂长
CameraBoom->bUsePawnControlRotation = true;          // 跟随控制器旋转

FollowCamera = CreateDefaultSubobject<UCameraComponent>(TEXT("FollowCamera"));
FollowCamera->SetupAttachment(CameraBoom, USpringArmComponent::SocketName);  // 挂到臂末端插槽
```

三个要点：

1. `CreateDefaultSubobject` **只能在构造函数里调用**，创建的组件会在 CDO（类默认对象）阶段就存在，编辑器里也能看到；
2. 名字用 `TEXT("CameraBoom")` 显式指定，否则组件在编辑器里显示为一串自动生成的名字；
3. `SetupAttachment(父组件, 插槽名)` 建立层级；不指定插槽默认挂父组件原点。

蓝图对照：构造函数里的这些代码 = 蓝图"添加组件"面板点出来的东西。**反过来也一样**——在角色蓝图子类里还能继续往这个 C++ 角色上加组件。

### 运行时创建组件

构造函数之外（比如 BeginPlay 里按需生成）要用另一套 API：

```cpp
UStaticMeshComponent* MeshComp = NewObject<UStaticMeshComponent>(this, TEXT("DynamicMesh"));
MeshComp->RegisterComponent();          // 注册后才参与渲染/碰撞/Tick
AddInstanceComponent(MeshComp);         // 记录到 Actor 的实例组件列表
```

记住配对关系：**构造期 `CreateDefaultSubobject`，运行期 `NewObject` + `RegisterComponent`**。用错会出现"组件不渲染/不碰撞"的问题。

## 写一个自己的组件

以一个常见的血量组件为例（`HealthComponent.h`）：

```cpp
#pragma once

#include "CoreMinimal.h"
#include "Components/ActorComponent.h"
#include "HealthComponent.generated.h"

UCLASS(ClassGroup = (Custom), meta = (BlueprintSpawnableComponent))
class MYTHIRD_API UHealthComponent : public UActorComponent
{
    GENERATED_BODY()

public:
    UHealthComponent();

protected:
    virtual void BeginPlay() override;

    UPROPERTY(EditAnywhere, Category = "Health", meta = (ClampMin = "0.0"))
    float MaxHealth = 100.f;

    UPROPERTY(VisibleAnywhere, Category = "Health")
    float CurrentHealth;

public:
    virtual void TickComponent(float DeltaTime, ELevelTick TickType,
                               FActorComponentFunction* ThisTickFunction) override;

    UFUNCTION(BlueprintCallable, Category = "Health")
    void ApplyDamage(float Amount);

    UFUNCTION(BlueprintPure, Category = "Health")
    float GetHealthPercent() const { return MaxHealth > 0.f ? CurrentHealth / MaxHealth : 0.f; }
};
```

`UCLASS` 上的两个说明符是组件专属的：

- `ClassGroup = (Custom)`：组件出现在编辑器"添加组件"面板的 Custom 分组下；
- `meta = (BlueprintSpawnableComponent)`：**允许在蓝图 Actor 的组件面板里直接添加它**（没有这个标记就只能 C++ 挂）。

在角色里使用：

```cpp
// PlayerCharacter.h
UPROPERTY(VisibleAnywhere, Category = "Health")
TObjectPtr<UHealthComponent> HealthComp;

// PlayerCharacter.cpp 构造函数
HealthComp = CreateDefaultSubobject<UHealthComponent>(TEXT("HealthComp"));
```

组件和 Actor 的函数签名差异（容易写错）：

| | Actor | 组件 |
|---|---|---|
| 每帧 | `Tick(float DeltaTime)` | `TickComponent(DeltaTime, TickType, ThisTickFunction)` |
| 开始 | `BeginPlay()` | `BeginPlay()`（同名） |

## Actor 生命周期（重点）

从出生到销毁，Actor 的关键节点顺序：

```
构造函数            ← CreateDefaultSubobject 在这里发生（编辑器里每次改属性也会跑）
    ↓
PostInitializeComponents   ← 组件都已就绪，可做依赖其他组件的初始化
    ↓
BeginPlay          ← 游戏正式开始，蓝图 Event BeginPlay 也在这一步被触发
    ↓
Tick (每帧)        ← 组件的 TickComponent 先后由更新组顺序决定
    ↓
EndPlay            ← 销毁/关卡切换时，做清理（解绑委托、撤计时器）
    ↓
析构函数
```

蓝图对照表：

| C++ | 蓝图 |
|---|---|
| 构造函数 | 构造脚本 (Construction Script) |
| `PostInitializeComponents` | 无直接对应 |
| `BeginPlay` | Event BeginPlay |
| `Tick(DeltaTime)` | Event Tick |
| `EndPlay(EndPlayReason)` | Event EndPlay（需手动添加） |
| `Destroy()` | Destroy Actor 节点 |

经验法则：

- **不依赖别人的初始化**放构造函数；**依赖组件就绪**放 `PostInitializeComponents`；**依赖游戏开始/所有 Actor 就位**放 `BeginPlay`；
- 重载任何虚函数都先调 `Super::`；
- 不需要 Tick 的组件在构造函数里关掉：`PrimaryComponentTick.bCanEverTick = false;`——省性能的好习惯；
- `EndPlay` 里解绑委托、清 Timer，否则下一关会触发已销毁对象的回调。

## 委托：组件向外界报事件

组件里最常用的通知方式是**动态多播委托**（对应蓝图第 10 章的**事件分发器**）：

```cpp
// HealthComponent.h 顶部，类外声明
DECLARE_DYNAMIC_MULTICAST_DELEGATE_OneParam(FOnDeath, AActor*, OwningActor);

UCLASS(ClassGroup = (Custom), meta = (BlueprintSpawnableComponent))
class UHealthComponent : public UActorComponent
{
    GENERATED_BODY()

public:
    // 蓝图可绑定（相当于事件分发器）
    UPROPERTY(BlueprintAssignable, Category = "Health")
    FOnDeath OnDeath;

    void ApplyDamage(float Amount)
    {
        CurrentHealth -= Amount;
        if (CurrentHealth <= 0.f)
        {
            CurrentHealth = 0.f;
            OnDeath.Broadcast(GetOwner());   // 广播：所有订阅者都会被调用
        }
    }
};
```

订阅方（C++）：

```cpp
// 在 PlayerCharacter::BeginPlay 里
HealthComp->OnDeath.AddDynamic(this, &APlayerCharacter::HandleDeath);

void APlayerCharacter::HandleDeath(AActor* DeadActor)
{
    // 死亡逻辑（对应蓝图第 6 章"死亡自定义事件"）
}
```

订阅方（蓝图）：选中组件 → 细节面板 Events 分组点 `OnDeath` 的 "+" —— 和事件分发器的绑定操作一模一样。

> `AddDynamic` 的回调必须是 `UFUNCTION()` 标记的函数（动态委托靠反射按名字找函数）。忘记解绑时，`EndPlay` 里用 `OnDeath.RemoveDynamic(this, ...)` 或 `Clear()` 清理。

## 常见坑

1. `CreateDefaultSubobject` 写到构造函数外 → 编译报错或运行时断言失败；
2. 组件指针没加 `UPROPERTY` → GC 不追踪，运行中变野指针崩溃（指针成员**必须**加宏，原因见 [常用宏与反射](/C++/4.常用宏与反射.html)）；
3. 在构造函数里访问别的 Actor / 关卡内容 → 那时世界还没建好，这类逻辑放 BeginPlay；
4. 蓝图里找不到自己的组件 → `UCLASS` 少了 `meta = (BlueprintSpawnableComponent)`；
5. `TickComponent` 签名抄成 `Tick` → 永远不会被调用（它不是虚函数重载）。

---

## 小结

- 组件三基类：`UActorComponent`（纯逻辑）/ `USceneComponent`（有变换）/ `UPrimitiveComponent`（有渲染碰撞）；
- 构造期 `CreateDefaultSubobject` + `SetupAttachment`，运行期 `NewObject` + `RegisterComponent`；
- 自定义组件加 `BlueprintSpawnableComponent` 才能在蓝图里添加；
- 生命周期：构造 → PostInitializeComponents → BeginPlay → Tick → EndPlay，按"依赖多少"选择初始化位置；
- 组件报事件用 `DECLARE_DYNAMIC_MULTICAST_DELEGATE` + `BlueprintAssignable`，就是蓝图的事件分发器。
