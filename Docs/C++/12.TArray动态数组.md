# TArray：UE 的动态数组

`SubPlayerCharacter` 里已经写过这样一段练习：

```cpp
// SubPlayerCharacter.h
TArray<int32> MyIntArray;

// SubPlayerCharacter.cpp
MyIntArray.Add(1);
MyIntArray.Add(2);
MyIntArray.Add(3);
MyIntArray.Add(4);

for (int32 i = 0; i < MyIntArray.Num(); ++i)
{
    int32 Element = MyIntArray[i];
    UE_LOG(LogTemp, Warning, TEXT("Index: %i; Element: %d"), i, Element);
}

MyIntArray.Add(5);
int32 ElementFive = MyIntArray[4];   // 新加的元素在末尾，下标 4
```

这就是 `TArray`——UE 里最常用的容器（对应标准库的 `std::vector`、蓝图里的 **Array 变量**）。本章把它的常用操作、内存行为和坑系统地过一遍。

> 为什么不用 `std::vector`？`TArray` 和 UE 反射 / 序列化 / 垃圾回收深度集成——`UPROPERTY()` 标记的 `TArray` 能被编辑器编辑、存盘、网络复制，元素里的 `UObject*` 能被 GC 正确跟踪，`std::vector` 都做不到（详见[第 4 章](/C++/4.常用宏与反射.md)）。**工程内一律用 UE 容器。**

---

## 一、创建与初始化

```cpp
TArray<int32> IntArr;                          // 空
TArray<int32> Filled(4, 0);                    // {0, 0, 0, 0}：4 个 0
TArray<int32> Copied = Filled;                 // 整体拷贝（深拷贝）
TArray<FString> StrArr = {TEXT("甲"), TEXT("乙")};  // 初始化列表

TArray<int32> Grown;
Grown.SetNum(10);        // 直接扩到 10 个元素（新增的 int 是未初始化的！）
Grown.Init(7, 10);       // 重新布置成 10 个 7
```

元素类型要求：能**拷贝构造 + 析构**。`int32` / `FString` / `FVector` / `UObject*` / 自定义 `USTRUCT` 都可以；非 UObject 的裸指针（`FMyStruct*`）不行——GC 不认识它，见[常见坑](#七常见坑汇总)。

## 二、添加与移除

### 添加家族

```cpp
TArray<FString> Arr;

Arr.Add(TEXT("甲"));            // 拷贝进数组：先有对象，再拷贝进去
Arr.Emplace(TEXT("乙"));        // 原地构造：直接在数组内存里构造，省一次拷贝
Arr += Arr;                     // 追加整个数组（同 Append）
Arr.Append(Other);              // 追加另一容器 / 指针区间
Arr.AddUnique(TEXT("甲"));      // 不存在才添加（已有则不动）
Arr.Insert(TEXT("头"), 0);      // 插到指定下标，后面元素全部后移（O(n)）
Arr.Push(TEXT("尾"));           // 等价 Add（尾进）
```

**Add vs Emplace**：`Add` 接一个现成对象（拷贝进容器），`Emplace` 接构造参数（容器内直接构造）。对 `FString`、`FVector` 这类有构造开销的类型，`Emplace` 更省。规则简单记：**临时对象塞进去用 Emplace**。

### 移除家族

```cpp
Arr.Remove(TEXT("乙"));        // 按值删：删掉【所有】相等元素（O(n)）
Arr.RemoveSingle(TEXT("甲"));  // 只删第一个相等的（O(n)，但找到即停）
Arr.RemoveAt(0);               // 按下标删，后面元素前移保持顺序（O(n)）
Arr.RemoveAtSwap(0);           // 按下标删，把末尾元素搬过来填坑（O(1)！）——顺序打乱
Arr.RemoveAll([](const FString& S) { return S.Len() > 3; });  // 按条件删
Arr.Pop();                     // 弹出末尾元素并返回
Arr.Empty();                   // 清空并释放内存（元素全析构）
Arr.Reset();                   // 清空但【保留】已分配内存（马上还要装东西时更快）
```

`RemoveAtSwap` 是 UE 特色性能技巧：不保持顺序的删除用 O(1) 完成——"敌人死亡时从 `TArray<AEnemy*>` 里移除自己"就是教科书场景（管理器列表不关心顺序）。

## 三、访问与遍历

```cpp
if (Arr.Num() > 0)             // Num() 是元素个数（不是容量！）
{
    FString& First = Arr[0];   // 越界？编辑器/Debug 下直接断言崩溃（好事，早暴露）
    FString& Last = Arr.Last();// 末尾元素；Last(1) 是倒数第二个
    FString  Top  = Arr.Top(); // 末尾元素的引用
}
```

三种遍历写法（都该用 `const auto&` 避免逐元素拷贝）：

```cpp
// ① 下标（需要索引时）
for (int32 i = 0; i < Arr.Num(); ++i) { UE_LOG(LogTemp, Log, TEXT("%d: %s"), i, *Arr[i]); }

// ② range-for（最常用）
for (const FString& S : Arr) { /* ... */ }

// ③ 迭代器（遍历中要增删时用，见常见坑）
for (auto It = Arr.CreateIterator(); It; ++It) { /* *It 取元素，It.RemoveCurrent() 安全删除 */ }
```

## 四、查找

```cpp
bool  bHas   = Arr.Contains(TEXT("甲"));                    // 有没有
int32 Index  = Arr.Find(TEXT("甲"));                        // 第一个相等的下标，没有返回 INDEX_NONE
int32 LastIx = Arr.FindLast(TEXT("甲"));                    // 最后一个相等的下标

// 谓词版（配 lambda，最灵活）
bool  bAnyBig   = Arr.ContainsByPredicate([](const FString& S) { return S.Len() > 10; });
int32 Ix        = Arr.IndexOfByPredicate(/* 同上 */);
auto* Found     = Arr.FindByPredicate(/* 同上 */);          // 返回指针，没找到是 nullptr

TArray<FString> Long = Arr.FilterByPredicate(/* 同上 */);   // 过滤出新数组
```

`Find` 返回 `INDEX_NONE`（-1）表示没找到——**判空用 `!= INDEX_NONE`，别拿 0 当"没找到"**（0 是合法下标）。

## 五、排序

```cpp
// 升序（int / float 等直接排）
IntArr.Sort();
IntArr.Sort([](int32 A, int32 B) { return A > B; });   // 降序：lambda 返回"A 是否应排在 B 前"

// 结构体 / 对象按字段排（AEnemy 为假设的敌人类）
EnemyArr.Sort([](const AEnemy& A, const AEnemy& B) {
    return A.GetHealth() > B.GetHealth();              // 血多的在前
});
```

`Sort` 是快排（快、**不稳定**）；`StableSort` 归并排（相等元素保持原相对顺序）；`HeapSort` 堆排（排序 + 后续还要频繁增删的场景）。日常 `Sort` 够用。

## 六、内存机制：Num / Max / Slack

`TArray` 和 `std::vector` 一样是"连续内存 + 预留容量"模型：

```
Num() = 实际元素数        ← 你关心的
Max() = 已分配容量        ← 引擎关心的
Slack = Max() - Num()     → 空闲槽位
```

- `Add` 时容量不够会**按约 1.5~2 倍扩容**并整体搬家（旧内存释放）——所以**扩容后所有指针/引用全部失效**；
- `Reserve(1000)`：预知要装很多时一次到位，避免反复搬家（例如循环里 `Add` 上千次前先 Reserve）；
- `Shrink()`：把尾部空闲容量裁掉（删了很多元素后想立即还内存）。

```cpp
TArray<int32> Big;
Big.Reserve(10000);        // 之后 Add 一万次不会触发扩容搬家
```

## 七、常见坑汇总

| 坑 | 说明与正确姿势 |
|---|---|
| **遍历中 Add / Remove** | range-for 里增删 = 未定义行为（迭代器失效）。要删用 `CreateIterator()` + `It.RemoveCurrent()`；或倒序下标循环 `for (int32 i = Arr.Num() - 1; i >= 0; --i)` |
| **越界访问** | `Arr[i]` 不检查范围但会断言——编辑器下崩溃是**保护**，别无视；先 `Num()` 判断或用 `IsValidIndex(i)` |
| **`UObject*` 元素没 GC** | 元素是指针时必须 `UPROPERTY()` 标记整个数组，否则 GC 看不见引用，对象可能被误回收（[第 4 章](/C++/4.常用宏与反射.md)） |
| **存非 UObject 莽指针** | `TArray<FMyStruct*>` 不被 GC 管理，容易悬垂。自定义数据用 `USTRUCT` 值类型存，或包成 `UObject*` |
| **Add 拷贝开销** | 大对象逐个 `Add` = 反复拷贝；用 `Emplace`、`MoveTemp(Obj)`（移动语义）或先 `Reserve` |
| **RemoveAtSwap 依赖顺序** | 图省事用了 Swap 删除，又在别处假设数组有序——顺序是乱的，别混用 |
| **`Find` 返回 0** | 0 是"下标 0"，不是"没找到"；判断用 `INDEX_NONE` |

## 八、蓝图互操作

```cpp
UPROPERTY(EditAnywhere, BlueprintReadWrite, Category = "Inventory")
TArray<FName> ItemIds;                       // 编辑器细节面板直接增删改（就是蓝图 Array 变量）

UPROPERTY(EditAnywhere)
TArray<TSubclassOf<AActor>> SpawnClasses;    // 编辑器里拖蓝图类进来，C++ 里 SpawnActor（第 9 章生成链）
```

- 蓝图侧的 Array 变量（For Each / Add / Remove Index…）操作的就是 `TArray`，C++ 暴露后在蓝图里同样能用这些节点；
- 网络复制：`UPROPERTY(Replicated)` 的 `TArray` 整体复制（元素多时考虑 `FastArraySerializer`，进阶话题）。

---

## 小结

- `TArray` = UE 版 `vector`：`Add/Emplace` 进、`[]`/`Num()` 用、`Remove` 系列出，`Reserve` 管容量；
- 删元素不保序用 `RemoveAtSwap`（O(1)），保序用 `Remove/RemoveAt`；
- 元素含 `UObject*` 必须 `UPROPERTY()`，否则 GC 会出事；
- 遍历中删除用迭代器或倒序循环；
- 配套容器一句话认识：`TSet`（去重集合）、`TMap`（键值对）、`TArrayView`（零拷贝数组切片视图）——用法同族，会 TArray 就都好上手。
