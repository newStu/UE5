# 动画类的 C++ 实现与蓝图状态机绑定（手写 PlayerAnim）

[蓝图篇的动画章节](/蓝图/2.动画创建/动画创建.md)里，"算速度"的逻辑是写在动画蓝图事件图表中的：`TryGetPawnOwner → Get Movement Component → Get Velocity → Vector Length XY → SET Speed`，一串节点每帧执行。这一章把这条逻辑**下沉到 C++**：手写一个继承 `UAnimInstance` 的 `UPlayerAnim` 类，负责缓存角色引用、每帧刷新 `Speed`；蓝图侧则只保留它最擅长的部分——**状态机与混合空间的可视化编排**。代码取自 `MyThird/Source/MyThird/Public/PlayerAnim.h` 与 `Private/PlayerAnim.cpp`。

## 分工：C++ 管数据，蓝图管表现

这是动画蓝图与 C++ 混用的标准模式——**逻辑层放 C++，表现层放蓝图**：

```
C++（UPlayerAnim，逻辑层）                    蓝图（AnimBP 子类，表现层）
NativeInitializeAnimation ─ 缓存角色/移动组件
        ↓ 每帧
NativeUpdateAnimation ─ 计算 Speed ──暴露──→ 状态机 / 混合空间横轴
                                             （Idle/Walk/Run 按速度混合）
```

| 层         | 内容                                       | 在哪做           |
| ---------- | ------------------------------------------ | ---------------- |
| 数据层     | 缓存 Character / MovementComponent 引用    | C++（本章）      |
| 数据层     | 每帧计算水平速度 Speed                     | C++（本章）      |
| 表现层     | 状态机组织动画状态                         | 蓝图 AnimGraph   |
| 表现层     | 混合空间按 Speed 混合 Idle / Run           | 蓝图 AnimGraph   |

这样分工的好处：变量计算不用拖节点、性能更好（原生代码每帧执行）、逻辑可以像普通 C++ 一样调试和版本管理；而状态机这种"看图才直观"的东西留在蓝图里编辑。

## 第一步：头文件声明

`PlayerAnim.h` 全文结构：

```cpp
#pragma once

#include "CoreMinimal.h"
#include "Animation/AnimInstance.h"
#include "GameFramework/CharacterMovementComponent.h"
#include "PlayerAnim.generated.h"   // UCLASS 必须的生成头，且必须放在 include 列表最后

class APlayerCharacter;   // 前置声明：头文件里只用指针，不必 include 完整头文件

UCLASS()
class MYTHIRD_API UPlayerAnim : public UAnimInstance
{
    GENERATED_BODY()

public:
    virtual void NativeInitializeAnimation() override;
    virtual void NativeUpdateAnimation(float DeltaTime) override;

    UPROPERTY(BlueprintReadOnly)
    TObjectPtr<APlayerCharacter> PlayerCharacter;

    UPROPERTY(BlueprintReadOnly)
    TObjectPtr<UCharacterMovementComponent> PlayerCharacterMovement;

    UPROPERTY(BlueprintReadOnly, Category="CPlus")
    float Speed = 0.f;   // 就地初始化，避免首次更新前蓝图读到未定义值
};
```

要点：

- 动画实例类的基类是 **`UAnimInstance`**——蓝图篇创建 AnimBP 时父类保持默认的 `AnimInstance`，就是它。我们现在是给这个父类写一个 C++ 中间层，蓝图再去继承 `UPlayerAnim`；
- 三个成员都标 `BlueprintReadOnly`：C++ 负责写，蓝图只读。这就是"数据下沉、表现上浮"的通道——**没有 `BlueprintReadOnly`，蓝图里的状态机根本看不到这些变量**；
- `#include "PlayerAnim.generated.h"` 不能省也不能放错位置：UCLASS 的反射代码由 UHT 生成在这个头里，漏掉它直接编译报错——宏相关的坑[第 4 章](/C++/4.常用宏与反射.md)有汇总；
- `TObjectPtr` + 前置声明的写法与[第 5 章](/C++/5.输入控制与第三人称相机.md)的 `PlayerCharacter` 一致，头文件能不 include 就不 include，缩短编译链。

对应关系（C++ 虚函数 ↔ 蓝图事件）：

| C++ 虚函数                  | 蓝图里的对应事件                        | 时机             |
| --------------------------- | --------------------------------------- | ---------------- |
| `NativeInitializeAnimation` | BlueprintInitializeAnimation 事件       | 动画实例初始化一次 |
| `NativeUpdateAnimation`     | BlueprintUpdateAnimation 事件（每帧）   | 每帧刷新         |

蓝图篇在事件图表里用的 `BlueprintUpdateAnimation`，其实就是这两个虚函数给蓝图留的重载入口——**蓝图重写事件 vs C++ 重写 Native 函数，走的是同一套调用链**。

## 第二步：初始化——缓存引用，只做一次

```cpp
void UPlayerAnim::NativeInitializeAnimation()
{
    Super::NativeInitializeAnimation();

    // TryGetPawnOwner 返回拥有该 AnimInstance 的 Pawn（动画蓝图挂在它的 Mesh 上）
    PlayerCharacter = Cast<APlayerCharacter>(TryGetPawnOwner());

    if (PlayerCharacter)
    {
        PlayerCharacterMovement = PlayerCharacter->GetCharacterMovement();
    }
}
```

- `TryGetPawnOwner` 是 `UAnimInstance` 自带的接口：动画实例不知道自己属于谁，得靠它反查**挂载这个动画蓝图的 Mesh 所属的 Pawn**。这和蓝图篇事件图表里拖的 `TryGetPawnOwner` 节点是同一个函数；
- 拿到后 `Cast` 成具体的 `APlayerCharacter`。失败（比如动画蓝图被预览窗口、AI 小兵等非玩家 Pawn 使用）时指针为空，后面的每帧更新会因判空而跳过——**不会崩溃，只是不更新**；
- 关键思路：**"获取一次，缓存起来"**。`Cast` 和 `GetCharacterMovement` 都是查找操作，放初始化里做一次就够，别放每帧执行的函数里（蓝图篇把 `TryGetPawnOwner` 链拖在 Update 事件后面，属于每帧重复获取，C++ 版顺手修正了这点）。

## 第三步：每帧更新——计算水平速度

```cpp
void UPlayerAnim::NativeUpdateAnimation(float DeltaTime)
{
    Super::NativeUpdateAnimation(DeltaTime);

    if (PlayerCharacterMovement)
    {
        Speed = UKismetMathLibrary::VSizeXY(PlayerCharacterMovement->Velocity);
    }
}
```

- `UKismetMathLibrary::VSizeXY` 就是蓝图节点 `Vector Length XY` 的 C++ 形态——数学库虽然挂在 "Kismet"（蓝图旧称）名下，但 C++ 里一样能直接调用；
- **为什么必须 XY 而不是三维长度**：跳跃/下落时 Z 轴速度很大，算进去会让 `Speed` 突增、动画错误地切进跑步。`VSizeXY` 过滤掉垂直分量，保证这个值只描述"在地面上跑多快"——这也是[蓝图篇](/蓝图/2.动画创建/动画创建.md)反复强调的同一个坑。至于被过滤掉的 Z 轴（跳跃状态机恰恰需要它），留到[拓展章节](/C++/7.拓展-为跳跃状态机暴露C++变量.md)再谈；
- 两个函数的第一行 `Super::` 调用不能省：父类 `UAnimInstance` 的 Native 版本还要做框架内部的初始化和更新，跳过它会出现难以定位的怪问题。

## 第四步：蓝图侧——创建以 UPlayerAnim 为父类的动画蓝图

C++ 类编译通过后，回到编辑器：

1. 内容浏览器右键 → 动画 → 动画蓝图；
2. 选择父类时，**不再用默认的 `AnimInstance`**，而是在搜索框里输入 `PlayerAnim` 选中我们的 C++ 类（找不到就先重启编辑器，见下方排查表）；
3. 骨骼仍然选角色网格体用的那套——这一步和蓝图篇完全一致。

> 如果新建的 C++ 类不出现在父类列表里，优先**重启编辑器**（让模块重新编译，比热重载可靠）——游戏模块本就依赖 Engine，`AnimInstance` 这类引擎类型的可见性一般不成问题，列表刷不出来基本都是编译/加载时机的事。

创建出来的蓝图**事件图表是空的**——原来那串 `TryGetPawnOwner → ... → SET Speed` 不需要了，变量 `Speed` 已经由 C++ 每帧写好。打开侧边的变量面板，能直接看到 `Speed`、`PlayerCharacter`、`PlayerCharacterMovement` 三个只读变量（带锁定图标），这就是 `BlueprintReadOnly` 暴露出来的。

## 第五步：绑定到角色网格体

与[蓝图篇](/蓝图/2.动画创建/动画创建.md)相同：角色蓝图 → 选中 Mesh 组件 → 细节面板 → 动画分类：

- 动画模式 (Animation Mode)：使用动画蓝图；
- 动画类 (Anim Class)：选刚创建的、以 `UPlayerAnim` 为父类的 AnimBP。

## 第六步：AnimGraph 里搭状态机，消费 C++ 变量

表现层编排与蓝图篇的[动画创建](/蓝图/2.动画创建/动画创建.md)操作相同，区别只在**数据来源**：

1. AnimGraph 右键新建**状态机**，输出接 Output Pose；
2. 双击进入状态机，在默认状态（即 Locomotion）里放入配好的混合空间节点（横轴 `Speed`，0 → 600，Idle ↔ Run）；
3. 把变量 **`Speed`** 连到混合空间横轴引脚——注意这是 C++ 每帧刷新的那个变量，不是蓝图自己 SET 的。

当前工程的状态机只有这一个状态：混合空间本身已经按速度完成 Idle ↔ Run 的平滑混合，没有第二个状态，也就暂时用不上转换条件。等以后要加跳跃、蹲伏等互斥动作时，才需要"多状态 + 转换条件"的编排——届时 C++ 侧还要补暴露跳跃所需的变量，思路见拓展章节[第 7 章](/C++/7.拓展-为跳跃状态机暴露C++变量.md)。

## 常见问题排查

| 症状                             | 检查                                                                          |
| -------------------------------- | ----------------------------------------------------------------------------- |
| 父类列表里找不到 `PlayerAnim`    | 重启编辑器让模块重新编译（比热重载可靠）；确认 C++ 编译无报错                     |
| 角色站着 T-Pose 不播动画         | Mesh 的动画模式是否为"使用动画蓝图"、Anim Class 是否指定                        |
| `Speed` 永远是 0                 | `TryGetPawnOwner` 返回的不是 `APlayerCharacter`（Cast 失败）；或 AnimBP 父类选错 |
| 蓝图事件图表里又写了 Update 逻辑 | 会和 `NativeUpdateAnimation` 并行跑，两边打架——C++ 已接管，事件图表留空       |
| 蓝图子类里改了 C++ 变量的值      | `BlueprintReadOnly` 只读，蓝图能改的是细节面板里的默认值，一般不需要动          |

## 小结

- 标准分工：**C++ 继承 `UAnimInstance` 管数据（缓存引用、每帧算 Speed），蓝图子类管表现（状态机、混合空间）**；
- `NativeInitializeAnimation` 里做一次 `TryGetPawnOwner → Cast → 缓存移动组件`，别把查找放每帧路径上；
- `NativeUpdateAnimation` 里用 `VSizeXY` 算水平速度，过滤 Z 轴，保证只描述"在地面上跑多快"；
- `BlueprintReadOnly` 是 C++ 与蓝图状态机之间的桥——没有它，AnimGraph 里看不到任何变量；
