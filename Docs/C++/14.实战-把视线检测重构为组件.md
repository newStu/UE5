# 实战：把视线检测重构为组件

第 13 章的视线检测直接写在 `EnemyCharacter` 里：`LineTraceActor` 算起点终点、`CanSeeActor` 发射线，能跑，但逻辑长在 Actor 身上——只有敌人这个类能用。想再做一个"会看人的监视摄像头"或"炮塔"，就得把整段代码复制过去。

这次把这套逻辑抽成一个自定义组件 `UMySceneComponent`（源码在 `Source/MyThird/Components/`），任何 Actor 挂上它就获得视线检测能力。这也是第 3 章[组件编写与生命周期](/C++/3.组件编写与生命周期.md)的实战落地。

---

## 一、重构前后：什么变了

| | 重构前（第 13 章） | 重构后（本章） |
|---|---|---|
| 逻辑位置 | `AEnemyCharacter` 成员函数 | `UMySceneComponent` 组件 |
| 射线起点 | `GetActorLocation()`（Actor 根位置） | `GetComponentLocation()`（组件自身位置） |
| 转身方式 | 直接 `SetActorRotation()` | `GetOwner()->SetActorRotation()` |
| 谁来 Tick | Actor 的 `Tick` | 组件的 `TickComponent` |
| 复用性 | 只有 EnemyCharacter 能用 | 任何 Actor 挂上即用 |

`EnemyCharacter` 里旧的两个函数保留为注释，方便对照。Actor 侧只剩三件事：**构造时创建组件、BeginPlay 时注入目标、Tick 时读结果**。

## 二、写组件类

### 选基类：为什么要 SceneComponent

第 3 章的规则：需要"摆在哪里"就继承 Scene 系，纯逻辑继承 `UActorComponent`。这里射线起点要有一个**可以在编辑器里拖动摆放的位置**（比如把"眼睛"放到脑袋高度），所以要继承 `USceneComponent`：

```cpp
// MySceneComponent.h
UCLASS( ClassGroup=(Custom), meta=(BlueprintSpawnableComponent) )
class MYTHIRD_API UMySceneComponent : public USceneComponent
{
    GENERATED_BODY()
    // ...
};
```

两个 `UCLASS` 说明符回顾：`ClassGroup` 决定它在编辑器"添加组件"面板的分组；`BlueprintSpawnableComponent` 允许蓝图 Actor 直接添加它。

### 接口设计：组件不自己找目标

```cpp
protected:
    // 追踪目标：由拥有者注入，组件自己不调用 GetPlayerCharacter
    TObjectPtr<AActor> TargetActor;

    // 检测结果缓存：TickComponent 每帧更新，外界读缓存不重复检测
    bool bCanSee = false;

public:
    // 注入目标（在拥有者的 BeginPlay 里调用）
    FORCEINLINE void SetTargetActor(AActor* Actor) { TargetActor = Actor; }

    // 读取最近一帧的检测结果
    FORCEINLINE bool CanSeeTargetActor() { return bCanSee; }
```

这是组件设计的核心原则：**"看谁"由外界决定，组件只负责"怎么看"**。如果组件内部写死 `GetPlayerCharacter`，它就永远只能看玩家；改成注入后，同一个组件可以看玩家、看另一个敌人、看任何 Actor。`FORCEINLINE` 内联访问器没有调用开销，是暴露简单读写接口的惯用写法。

## 三、Actor API → 组件 API 的换算

逻辑搬进组件后，几处 API 要"翻译"：

| 干什么 | 在 Actor 里 | 在组件里 |
|---|---|---|
| 取位置 | `GetActorLocation()` | `GetComponentLocation()` |
| 转身 | `SetActorRotation(R)` | `GetOwner()->SetActorRotation(R)` |
| 每帧 | `Tick(DeltaTime)` | `TickComponent(DeltaTime, TickType, ThisTickFunction)` |
| 找世界 | `GetWorld()` | `GetWorld()`（组件也有，内部转发给 Owner） |
| 我是谁 | `this` | `GetOwner()` |

最容易忽略的是第二行：组件**不是** Actor，`SetActorRotation` 根本不是组件的方法，必须先 `GetOwner()` 拿到宿主 Actor 再转。反过来，"取位置"用组件自己的 `GetComponentLocation()`——这正是用 SceneComponent 的意义：组件挂在不同位置，检测起点就跟着变。

检测本体与第 13 章一致，只列差异：

```cpp
bool UMySceneComponent::LineTrace()
{
    if (TargetActor == nullptr) return false;          // 目标未注入

    FVector Start = GetComponentLocation();            // ← 组件位置，不是 Actor 位置
    FVector End = TargetActor->GetActorLocation();

    TArray<const AActor*> IgnoreActors = {GetOwner(), TargetActor};  // 忽略宿主和目标
    if (CanSeeActor(Start, End, IgnoreActors))
    {
        FRotator DirectRotation = UKismetMathLibrary::FindLookAtRotation(Start, End);
        GetOwner()->SetActorRotation(DirectRotation);  // ← 通过 GetOwner 转身
        return true;
    }
    return false;
}

void UMySceneComponent::TickComponent(float DeltaTime, ELevelTick TickType,
                                      FActorComponentTickFunction* ThisTickFunction)
{
    Super::TickComponent(DeltaTime, TickType, ThisTickFunction);
    bCanSee = LineTrace();    // 每帧检测一次，更新缓存
}
```

忽略列表也顺势改成了参数 `IgnoreActors`：调用方传 `{GetOwner(), TargetActor}` 进来，`CanSeeActor` 内部用 `QueryParams.AddIgnoredActors(IgnoreActors)` 一次性加入——比逐个 `AddIgnoredActor` 更通用。

## 四、在 EnemyCharacter 里挂载

### 声明与创建

```cpp
// EnemyCharacter.h
// 视线检测组件：检测与转身逻辑都封装在组件里
UPROPERTY(EditAnywhere)
TObjectPtr<UMySceneComponent> LookComponents;

// EnemyCharacter.cpp 构造函数
LookComponents = CreateDefaultSubobject<UMySceneComponent>(TEXT("Look Components"));
LookComponents->SetupAttachment(RootComponent);   // 挂到根组件（胶囊体）上
```

挂接后敌人的组件树：

```
CapsuleComponent (根)
├── Mesh（骨骼网格体）
└── Look Components ← 新增，可在编辑器里拖动位置当"眼睛"
```

### 注入目标与读取结果

```cpp
void AEnemyCharacter::BeginPlay()
{
    Super::BeginPlay();
    TargetCharacter = UGameplayStatics::GetPlayerCharacter(this, 0);
    LookComponents->SetTargetActor(TargetCharacter);   // 注入给组件
}

void AEnemyCharacter::Tick(float DeltaTime)
{
    Super::Tick(DeltaTime);
    // 读缓存标志，不会重复发射射线（检测在组件的 TickComponent 里已完成）
    bCanSeePlayer = LookComponents->CanSeeTargetActor();

    if (bCanSeePlayer)
    {
        UE_LOG(LogTemp, Warning, TEXT("Can See Player %s"), *TargetCharacter->GetName());
    }
}
```

一帧内的调用链：

```
AEnemyCharacter::Tick
    └─ LookComponents->CanSeeTargetActor()   ← 只是读 bCanSee 缓存

UMySceneComponent::TickComponent（组件自己的 Tick）
    └─ LineTrace()
        ├─ CanSeeActor()      ← 真正发射线
        └─ GetOwner()->SetActorRotation()
```

注意时序细节：Actor 的 Tick 和组件的 TickComponent 谁先谁跑由更新组顺序决定，所以 Actor 在自己 Tick 里读到的 `bCanSee` 可能是"上一帧"的结果——对视线检测这种逻辑完全无感，但做精确顺序敏感的逻辑时要记得两者**不保证**先后。

## 五、常见坑

1. **组件指针没加 `UPROPERTY`** → GC 不追踪，运行中变野指针崩溃（原因见[第 4 章](/C++/4.常用宏与反射.md)）；
2. **在组件里直接 `SetActorRotation`** → 编译不过，那是 Actor 的方法；必须 `GetOwner()->SetActorRotation`；
3. **`SetupAttachment` 忘写** → 组件不在根组件的层级里，其变换不随 Actor 移动，射线起点会"停在原地"；
4. **`SetTargetActor` 放构造函数** → 构造阶段世界尚未初始化，`GetPlayerCharacter` 拿到 nullptr；注入目标的活放 BeginPlay；
5. **`CreateDefaultSubobject` 写到构造函数外** → 报错；运行期动态加组件用 `NewObject` + `RegisterComponent`（见[第 3 章](/C++/3.组件编写与生命周期.md)）；
6. **蓝图里找不到该组件** → `UCLASS` 少了 `meta = (BlueprintSpawnableComponent)`。

## 小结

- 抽组件的判断标准：这段能力是否可能被**别的 Actor** 复用？是就下放成组件；
- 需要可摆放的位置 → 继承 `USceneComponent`，起点用 `GetComponentLocation()`；
- 组件不自己找目标：目标由拥有者 BeginPlay 时通过 `SetTargetActor` **注入**，检测结果缓存成 `bCanSee` 供外界读取；
- Actor 侧只剩三步：构造 `CreateDefaultSubobject` + `SetupAttachment`，BeginPlay 注入，Tick 读结果；
- 组件操作 Actor 一律经过 `GetOwner()`。
