# 常用宏与反射（UPROPERTY / UFUNCTION / UCLASS）

前几章里反复出现 `UPROPERTY(EditAnywhere)`、`UCLASS()`、`GENERATED_BODY()` 这些"不是标准 C++"的写法。本章集中讲清楚：它们是什么、怎么选、有哪些坑。示例均取自 `MyThird` 工程的真实代码。

---

## 一、这是什么？为什么需要这些"特殊语法"

UE 在标准 C++ 之上构建了一套 **反射（Reflection）系统**。C++ 本身不支持运行时检查类的成员、属性等信息，而 UE 的编辑器、蓝图、网络同步、垃圾回收（GC）、序列化都依赖这些信息。

工作原理：

1. 你在头文件里写 `UPROPERTY()`、`UCLASS()` 这类 **宏标记**；
2. 编译前，**UHT（UnrealHeaderTool）** 扫描头文件，根据这些标记生成代码到 `.generated.h` / `.gen.cpp` 中；
3. 生成的代码把类、属性、函数注册进 UE 的反射系统（`UClass`、`FProperty`、`UFunction` 等）。

因此这些宏不是"装饰性注释"，而是 **给 UHT 看的指令**，决定了：

- 变量能否在编辑器里显示、能否被蓝图读写；
- 函数能否在蓝图里调用、能否作为事件；
- 对象能否被 GC 追踪、能否网络复制。

---

## 二、宏总览

| 宏 | 作用对象 | 用途 |
|---|---|---|
| `UCLASS()` | class 声明之上 | 把类注册给 UE 反射系统，可指定 Blueprintable、config 等 |
| `USTRUCT()` | struct 声明之上 | 反射结构体（如 `FMyStruct`），支持蓝图变量 |
| `UENUM()` | enum 声明之上 | 反射枚举，配合 `BlueprintType` 可在蓝图中使用 |
| `UINTERFACE()` | interface 声明之上 | 声明 UE 接口的模板部分 |
| `UPROPERTY()` | 成员变量 | 暴露给编辑器 / 蓝图 / GC / 网络 |
| `UFUNCTION()` | 成员函数 | 暴露给蓝图 / 作为 RPC / 作为事件 |
| `GENERATED_BODY()` | 类内部 | UHT 生成代码的插入点，**必须写在类体最前面** |

### 固定骨架

```cpp
#pragma once

#include "CoreMinimal.h"
#include "GameFramework/Character.h"
#include "PlayerCharacter.generated.h"   // ← 必须是最后一个 #include，且文件名 = 类所在头文件名

UCLASS()
class MYTHIRD_API APlayerCharacter : public ACharacter
{
    GENERATED_BODY()                     // ← 类体第一行

public:
    APlayerCharacter();

protected:
    virtual void BeginPlay() override;

    UPROPERTY(EditAnywhere)              // ← 你选中的这行：变量可在编辑器任意处编辑
    float testLen;
};
```

常见错误：
- `#include "XXX.generated.h"` 不在 include 列表 **最后** → 编译报错；
- 改动宏后不重新编译 → UHT 没重新生成代码，编辑器里看不到变化；
- 忘写 `GENERATED_BODY()` → UHT 报错 "Missing GENERATED_BODY macro"。

## 三、UPROPERTY 详解（重点）

`UPROPERTY()` 括号里填 **说明符（Specifier）**，多个用逗号分隔。

### 3.1 编辑器可见性：Edit 系列 vs Visible 系列

| 说明符 | 编辑器中可修改？ | 典型用途 |
|---|---|---|
| `EditAnywhere` | ✅ 原型 & 实例都能改 | 大部分可调参数 |
| `EditDefaultsOnly` | ✅ 仅原型（蓝图/Cpp 默认值） | 玩家改不了的配置 |
| `EditInstanceOnly` | ✅ 仅场景中摆放的实例 | 只调关卡里这一只怪 |
| `VisibleAnywhere` | ❌ 只读显示 | 运行时算出来的值，方便调试查看 |
| `VisibleDefaultsOnly` | ❌ 只读，仅原型 | 同上 |
| `VisibleInstanceOnly` | ❌ 只读，仅实例 | 同上 |

**两轴理解**：
- **Edit / Visible**：能不能改（Edit 能改，Visible 只读展示）；
- **Anywhere / DefaultsOnly / InstanceOnly**：在哪显示（原型+实例 / 只原型 / 只实例）。

> "原型（Defaults / CDO）"= 类的默认对象，蓝图编辑器里改的就是它；
> "实例（Instance）"= 场景中实际摆放的每个 Actor。

本项目 `MyThirdCharacter.h` 中的实际例子：

```cpp
// 相机臂：只读展示 + 蓝图只读 + 归到 Camera 分类
UPROPERTY(VisibleAnywhere, BlueprintReadOnly, Category = Camera, meta = (AllowPrivateAccess = "true"))
class USpringArmComponent* CameraBoom;

// 输入参数：可编辑 + 蓝图只读 + 归到 Input 分类
UPROPERTY(EditAnywhere, BlueprintReadOnly, Category = Input, meta = (AllowPrivateAccess = "true"))
class UInputMappingContext* DefaultMappingContext;
```

### 3.2 蓝图交互：Blueprint 系列

| 说明符 | 蓝图端效果 |
|---|---|
| `BlueprintReadWrite` | 蓝图可 **读 + 写** |
| `BlueprintReadOnly` | 蓝图 **只读**（C++ 向蓝图单向传值） |
| `meta = (BindWidget)` | 允许在 Widget 蓝图中绑定同名控件（仅 UserWidget） |

`MyThirdCharacter.h` 的模式 —— `EditAnywhere + BlueprintReadOnly` 表示：**设计师在编辑器里调，蓝图里能查，但不能在蓝图里改**。

### 3.3 分类显示：Category

```cpp
UPROPERTY(EditAnywhere, Category = "Combat|Damage")
float BaseDamage;
```

编辑器细节面板里会按 `Combat → Damage` 分组显示，支持 `|` 嵌套子分类。

### 3.4 其他常用说明符

| 说明符 | 用途 |
|---|---|
| `Replicated` | 属性网络同步（服务端 → 客户端），需配合 `GetLifetimeReplicatedProps` |
| `ReplicatedUsing = OnXxxChanged` | 同步 + 回调（收到同步值时调 `OnXxxChanged`） |
| `SaveGame` | 参与 SaveGame 序列化 |
| `Transient` | 不参与序列化，纯运行时临时值 |
| `DuplicateTransient` | 复制对象时不复制该值 |
| `AdvancedDisplay` | 在编辑器里折叠到"高级"区域 |

### 3.5 meta 元数据（括在 `meta = (...)` 里）

| meta 键 | 用途 |
|---|---|
| `AllowPrivateAccess = "true"` | **private 成员**要暴露给蓝图/编辑器时必须加 |
| `ClampMin = "0.0"` | 编辑器数值滑条最小值（还有 `ClampMax`、`UIMin/Max`） |
| `DisplayName = "显示名"` | 编辑器/蓝图中显示别名 |
| `EditCondition = "bEnabled"` | 只有 `bEnabled == true` 时该属性才可编辑 |
| `Units = "Centimeters"` | 单位显示 |

```cpp
private:
    UPROPERTY(EditAnywhere, Category = "Stats", meta = (AllowPrivateAccess = "true"))
    float Health;

    UPROPERTY(EditAnywhere, Category = "Stats", meta = (ClampMin = "0.0", ClampMax = "100.0"))
    float Power;
```

> ⚠️ 没有 `UPROPERTY()` 的裸指针 **不参与 GC**，对象可能被回收成野指针 —— 这是 UE 里必须给指针加 `UPROPERTY()` 的核心原因之一（`UObject*`、`AActor*`、组件指针都要加）。

## 四、UFUNCTION 详解

### 4.1 蓝图交互

| 说明符 | 含义 |
|---|---|
| `BlueprintCallable` | 蓝图可调用该 C++ 函数 |
| `BlueprintImplementableEvent` | **函数体在蓝图中实现**，C++ 只声明不定义（调用 `exec_` 版本转发到蓝图） |
| `BlueprintNativeEvent` | C++ 提供默认实现（`ReceiveXxx`），蓝图可覆盖。C++ 内调用要走 `Xxx_Implementation()` |
| `BlueprintPure` | 纯函数（无副作用，无执行引脚，如 getter） |

```cpp
// 蓝图可调用
UFUNCTION(BlueprintCallable, Category = "Combat")
void Attack();

// 蓝图实现，C++ 只声明
UFUNCTION(BlueprintImplementableEvent, Category = "Combat")
void OnAttack();

// C++ 有默认实现，蓝图可选覆盖
UFUNCTION(BlueprintNativeEvent, Category = "Combat")
void OnDamaged(float Damage);
virtual void OnDamaged_Implementation(float Damage);  // 注意这个签名
```

### 4.2 RPC 网络函数

```cpp
UFUNCTION(Server, Reliable, WithValidation)  // 客户端 → 服务端
void ServerFire();

UFUNCTION(Client, Reliable)                  // 服务端 → 该 Actor 所属客户端
void ClientHitFeedback();

UFUNCTION(NetMulticast, Reliable)            // 服务端 → 所有客户端
void MulticastExplode();
```

- `Reliable`：保证送达（占带宽，重要事件用）；
- `Unreliable`：可丢弃（高频表现类，如特效位置）；
- RPC 只能被 **复制了的 Actor** 调用才有意义。

### 4.3 其他

| 说明符 | 用途 |
|---|---|
| `Category = "xxx"` | 蓝图节点分类 |
| `BlueprintSetter` / `BlueprintGetter` | 配合 BlueprintReadOnly/WriteOnly 的 set/get |
| `Exec` | 运行时可按 `~` 键在控制台直接输入调用（调试利器） |

## 五、UCLASS 说明符

本项目 `MyThirdCharacter.h` 的例子：

```cpp
UCLASS(config = Game)   // 类的配置项读写 Game.ini
class AMyThirdCharacter : public ACharacter
```

常用说明符：

| 说明符 | 用途 |
|---|---|
| `Blueprintable` | 允许基于该 C++ 类创建蓝图子类（`ACharacter` 系默认可，普通 `UObject` 默认不可） |
| `NotBlueprintable` | 禁止创建蓝图子类 |
| `config = Game` | 用 `UConfig` 属性配合 ini 存取 |
| `minimalapi` | 只导出最小 API（本项目 `MyThirdGameMode.h` 用了），减少 DLL 导出量，其他模块无法 dynamic_cast 到它 |
| `BlueprintType` | 该类可作为蓝图中的变量类型 |
| `EditInlineNew` / `HideCategories` | 编辑器细节面板行为 |

## 六、USTRUCT 与 UENUM

```cpp
USTRUCT(BlueprintType)
struct FMyStats
{
    GENERATED_BODY()

    UPROPERTY(EditAnywhere, BlueprintReadWrite)
    float Health = 100.f;

    UPROPERTY(EditAnywhere, BlueprintReadWrite)
    float Mana = 50.f;
};
```

- `USTRUCT` 是 **值类型**：作为 `UPROPERTY` 成员时整体复制、随宿主 GC，不像 `UObject` 是引用类型；
- `BlueprintType` 让结构体能在蓝图里声明变量；
- 结构体里也可以用 `EditAnywhere` 等，规则同上。

```cpp
UENUM(BlueprintType)
enum class EWeaponType : uint8
{
    Sword   UMETA(DisplayName = "剑"),
    Bow     UMETA(DisplayName = "弓"),
    Staff   UMETA(DisplayName = "法杖")
};
```

- 反射枚举 **必须** 是 `uint8` 底层类型；
- `UMETA(DisplayName = "...")` 控制编辑器/蓝图里显示的名字；
- 配合 `UPROPERTY(EditAnywhere)` 后，编辑器里会自动变成下拉框。

## 七、事件委托（宏家族，配合 UPROPERTY）

```cpp
// 声明（放在类外或 .h 顶部）
DECLARE_DYNAMIC_MULTICAST_DELEGATE_OneParam(FOnHealthChanged, float, NewHealth);

UCLASS()
class APlayerCharacter : public ACharacter
{
    GENERATED_BODY()

    // 蓝图可绑定的委托属性（BlueprintAssignable 才能在蓝图里 Bind Event）
    UPROPERTY(BlueprintAssignable, Category = "Events")
    FOnHealthChanged OnHealthChanged;
};
```

- `DECLARE_DYNAMIC_*` 系列：支持蓝图（序列化友好），参数需要注册；
- `DECLARE_*`（非 DYNAMIC）：仅 C++，性能更好；
- 后缀 `_OneParam` / `_TwoParams` / `_ThreeParams`… 对应参数个数，最多 9 个（`FourParams` 拼写注意）。

## 八、速查：最常用的组合模板

```cpp
// 1. 设计师可调的参数（最常见）
UPROPERTY(EditAnywhere, Category = "Stats", meta = (ClampMin = "0.0"))
float MaxHealth = 100.f;

// 2. 只读调试值
UPROPERTY(VisibleAnywhere, Category = "Debug")
float CurrentSpeed;

// 3. private 成员暴露给蓝图
private:
    UPROPERTY(EditAnywhere, BlueprintReadOnly, meta = (AllowPrivateAccess = "true"))
    float PrivateButEditable;

// 4. 组件指针（必须 UPROPERTY，否则 GC 野指针）
UPROPERTY(VisibleAnywhere, BlueprintReadOnly, Category = Camera, meta = (AllowPrivateAccess = "true"))
TObjectPtr<USpringArmComponent> CameraBoom;   // UE5 推荐用 TObjectPtr<> 代替裸指针

// 5. 蓝图可调用的函数
UFUNCTION(BlueprintCallable, Category = "Combat")
void Attack();

// 6. 子类引用（编辑器里可选拖入）
UPROPERTY(EditAnywhere, Category = "Combat")
TSubclassOf<UDamageType> DamageTypeClass;
```

## 九、常见坑汇总

1. **`.generated.h` 必须是最后一个 include**，且类必须写在 `.h`（UHT 只处理头文件）。
2. **改了宏没重编译** → 编辑器里没生效。改宏必须重新编译 C++（热载有时不可靠，重启编辑器最稳）。
3. **private 成员 + BlueprintReadOnly** → 不加 `meta = (AllowPrivateAccess = "true")` 会编译报错。
4. **裸 `UObject*` 指针不加 UPROPERTY** → GC 不追踪，对象被回收后成野指针，崩溃难查。
5. `BlueprintImplementableEvent` **不能** 是 `virtual`，也不写函数体；`BlueprintNativeEvent` 要声明 `Xxx_Implementation`。
6. 反射枚举底层必须是 `uint8`。
7. `Edit*` 与 `Visible*` **互斥**，同一属性不能同时用。
8. 函数想出现在蓝图里，参数和返回值类型也必须是蓝图支持的类型（反射类型、`FString`、`float` 等；不支持的如 `std::string`、模板参数等不行）。

## 十、记忆框架

```
宏 = 给 UHT 的注册指令
├── 类级：UCLASS / USTRUCT / UENUM → 这个类型进反射系统
├── 属性级：UPROPERTY → 这个变量给谁看/给谁改
│     ├── 给编辑器：Edit*（可改）/ Visible*（只读）
│     ├── 给蓝图：BlueprintReadWrite / BlueprintReadOnly
│     └── 给系统：Replicated（网络）/ GC（指针必须加）
└── 函数级：UFUNCTION → 这个函数给谁调
      ├── BlueprintCallable：蓝图调 C++
      ├── BlueprintImplementableEvent / BlueprintNativeEvent：C++ 调蓝图
      └── Server / Client / NetMulticast：RPC 网络调用
```
