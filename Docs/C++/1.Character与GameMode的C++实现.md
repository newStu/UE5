# Character 与 GameMode 的 C++ 实现

本节用 C++ 重新实现 [蓝图第 1 章「创建角色移动」](/蓝图/1.创建角色移动/创建角色移动.html) 搭好的骨架：自定义 **游戏模式 (GameMode)** 与 **角色 (Character)**，并把角色设为 GameMode 的默认 Pawn。代码全部来自本工程的 `MyThird` C++ 工程（`Source/MyThird/` 目录）。

整体链路和蓝图版完全一样，只是"在哪做"不同：

> 蓝图版：项目设置（默认 GameMode）→ GameMode 蓝图（默认 Pawn 类）→ Character 蓝图
> C++ 版：项目设置（默认 GameMode）→ `AMyThirdGameMode`（默认 Pawn 类）→ `AMyThirdCharacter`

**核心思路：C++ 写逻辑，蓝图配资源。** 网格体、动画蓝图这类美术资源引用不写死在 C++ 里，而是建一个 `BP_ThirdPersonCharacter` 蓝图子类去配置——这正是模板代码 `MyThirdCharacter.cpp` 里注释说明的做法。

---

## 从模板工程说起

`MyThird` 是 Third Person 模板生成的 C++ 工程，`Source/MyThird/` 下有四个关键文件：

| 文件 | 内容 |
|---|---|
| `MyThirdCharacter.h / .cpp` | 第三人称角色：相机臂、相机、移动/视角输入 |
| `MyThirdGameMode.h / .cpp` | 游戏模式：指定默认 Pawn |
| `PlayerCharacter.h / .cpp` | 自己练习新建的角色类 |

> 新建 C++ 类的方法：编辑器菜单 **工具 → 新建 C++ 类**，选好父类（Character / GameMode Base…）后 UE 会自动生成 `.h` / `.cpp` 骨架并触发编译。编译完成后，这个类会出现在蓝图编辑器"所有类"列表里，可以像普通类一样被继承成蓝图。

## GameMode：指定默认 Pawn

`MyThirdGameMode.h`：

```cpp
UCLASS(minimalapi)
class AMyThirdGameMode : public AGameModeBase
{
    GENERATED_BODY()

public:
    AMyThirdGameMode();
};
```

`MyThirdGameMode.cpp`：

```cpp
AMyThirdGameMode::AMyThirdGameMode()
{
    // set default pawn class to our Blueprinted character
    static ConstructorHelpers::FClassFinder<APawn> PlayerPawnBPClass(
        TEXT("/Game/ThirdPerson/Blueprints/BP_ThirdPersonCharacter"));
    if (PlayerPawnBPClass.Class != NULL)
    {
        DefaultPawnClass = PlayerPawnBPClass.Class;
    }
}
```

对照蓝图第 1 章"游戏模式绑定创建的角色"一步：蓝图里是在**类设置**面板把 Default Pawn Class 拉成角色蓝图；C++ 里就是在**构造函数**里给 `DefaultPawnClass` 赋值。

几个要点：

- `ConstructorHelpers::FClassFinder` 只能在**构造函数**里用，按内容路径查找蓝图类；`static` 保证只查找一次；
- `DefaultPawnClass` 是 `AGameModeBase` 自带的属性，等价于蓝图里的"默认 Pawn 类"设置；
- 找不到类不会直接崩溃（`if` 判空），但玩家会出场成默认的灰色小球 Pawn——这是"没绑上角色"时最常见的现象；
- `UCLASS(minimalapi)` 表示只导出最小 API，其他模块无法对它做 `dynamic_cast`，模板类用它减小 DLL 导出量。

> 之后在**项目设置 → 地图和模式**里把默认 GameMode 指到 `BP_ThirdPersonGameMode`（或直接用 C++ 类），链路就通了——这步和蓝图版完全一样。

## Character：构造函数做初始配置

蓝图版角色里"摆组件、调参数"的工作，C++ 版全部集中在**构造函数**（`MyThirdCharacter.cpp`）：

```cpp
AMyThirdCharacter::AMyThirdCharacter()
{
    // 碰撞胶囊大小
    GetCapsuleComponent()->InitCapsuleSize(42.f, 96.0f);

    // 控制器旋转时不带动角色本体（只影响相机）
    bUseControllerRotationPitch = false;
    bUseControllerRotationYaw = false;
    bUseControllerRotationRoll = false;

    // 角色朝移动方向旋转（对应蓝图"角色旋转配置"那步）
    GetCharacterMovement()->bOrientRotationToMovement = true;
    GetCharacterMovement()->RotationRate = FRotator(0.0f, 500.0f, 0.0f);

    // 跳跃/移动手感参数
    GetCharacterMovement()->JumpZVelocity = 700.f;
    GetCharacterMovement()->AirControl = 0.35f;
    GetCharacterMovement()->MaxWalkSpeed = 500.f;

    // 相机臂 + 相机（对应蓝图第 3 章"添加弹簧臂和相机组件"）
    CameraBoom = CreateDefaultSubobject<USpringArmComponent>(TEXT("CameraBoom"));
    CameraBoom->SetupAttachment(RootComponent);
    CameraBoom->TargetArmLength = 400.0f;
    CameraBoom->bUsePawnControlRotation = true;

    FollowCamera = CreateDefaultSubobject<UCameraComponent>(TEXT("FollowCamera"));
    FollowCamera->SetupAttachment(CameraBoom, USpringArmComponent::SocketName);
    FollowCamera->bUsePawnControlRotation = false;
}
```

- `bOrientRotationToMovement = true` + `bUseControllerRotationYaw = false`：就是蓝图里"移动时朝向移动方向 + 鼠标驱动视角"那套配置的代码写法；
- `CreateDefaultSubobject` 创建组件（蓝图里的"添加组件"），`SetupAttachment` 挂到父组件上；
- 手感参数（跳跃力、速度等）写在这里是"代码默认值"，之后在角色蓝图子类的细节面板里还能覆盖——模板注释里专门提醒：**调参优先去蓝图改，不用重新编译 C++**。

> 网格体和动画蓝图为什么不在 C++ 里设？模板同样留了注释：这类内容引用放在蓝图资产 `BP_ThirdPersonCharacter` 里配置，避免 C++ 代码直接依赖具体资源路径。

## 自己新建一个 Character 类

`PlayerCharacter.h` 是用"新建 C++ 类"生成的练习类，骨架如下：

```cpp
UCLASS()
class MYTHIRD_API APlayerCharacter : public ACharacter
{
    GENERATED_BODY()

public:
    APlayerCharacter();

protected:
    virtual void BeginPlay() override;

    UPROPERTY(EditAnywhere)
    float testLen;

public:
    virtual void Tick(float DeltaTime) override;
    virtual void SetupPlayerInputComponent(class UInputComponent* PlayerInputComponent) override;
};
```

每一行的含义：

- `UCLASS()`：把类注册进 UE 反射系统（详见 [常用宏与反射](/C++/4.常用宏与反射.html)）；
- `MYTHIRD_API`：模块导出宏，让别的模块能链接这个类；
- `GENERATED_BODY()`：UHT 生成代码的插入点，必须写在类体最前面；
- `UPROPERTY(EditAnywhere)`：变量出现在编辑器细节面板，原型和实例都能改；
- `BeginPlay` / `Tick` / `SetupPlayerInputComponent`：三个最常重载的虚函数，见下表。

## 生命周期入口：蓝图事件 ↔ C++ 虚函数

| 蓝图里的节点 | C++ 对应 | 说明 |
|---|---|---|
| 构造脚本 (Construction Script) | 构造函数 + `OnConstruction` | 编辑器里摆放/改属性时也会执行 |
| Event BeginPlay | `virtual void BeginPlay()` | 游戏开始时执行一次，记得调 `Super::BeginPlay()` |
| Event Tick | `virtual void Tick(float DeltaTime)` | 每帧执行，不用时在构造函数里 `PrimaryActorTick.bCanEverTick = false;` 省性能 |
| 输入事件绑定 | `SetupPlayerInputComponent` | Pawn 专属，见 [增强输入系统](/C++/2.增强输入系统的C++绑定.html) |

`BeginPlay` 的标准写法：

```cpp
void APlayerCharacter::BeginPlay()
{
    Super::BeginPlay();   // 先调父类，别忘
    // 自己的逻辑...
}
```

> `Super::` 调用父类实现是 UE C++ 的硬规矩：父类（如 `ACharacter`）的 BeginPlay 里往往有初始化组件、触发蓝图 BeginPlay 的工作，漏掉会出现"蓝图 Event BeginPlay 不执行"这类诡异问题。

## 改完代码之后

1. 在编辑器里点 **编译 (Compile)**，或关闭编辑器后在 IDE 里编译再启动（宏改动较大时更稳）；
2. 修改 `UPROPERTY` / `UFUNCTION` 这类反射宏后必须重新编译，否则 UHT 生成的代码和头文件不一致，编辑器里看不到效果；
3. C++ 类默认不会自动出现在场景里——要么让 GameMode 用它（改 `DefaultPawnClass`），要么右键建蓝图子类 `BP_PlayerCharacter` 再往关卡里摆。

---

## 小结

- GameMode 的"默认 Pawn 类"= 构造函数里给 `DefaultPawnClass` 赋值（`ConstructorHelpers::FClassFinder` 找蓝图）；
- Character 的"摆组件 + 调参数"= 构造函数里 `CreateDefaultSubobject` + 一堆赋值；
- 蓝图事件图表的入口（BeginPlay / Tick）对应 C++ 的重载虚函数，别忘了 `Super::`；
- 下一章：[增强输入系统的 C++ 绑定](/C++/2.增强输入系统的C++绑定.html)——把蓝图版"绑定 IMC / 绑定 IA"搬进 `SetupPlayerInputComponent`。
