# 输入控制与第三人称相机（手写 PlayerCharacter）

[第 2 章](/C++/2.增强输入系统的C++绑定.md)里我们用模板生成的 `MyThirdCharacter` 演示了增强输入的绑定方式。这一章把整套流程**从零手写**一遍：不靠模板，自己在 `APlayerCharacter` 里搭相机组件、绑输入、写移动和视角响应，并理清"鼠标转相机、WASD 相对相机移动"的完整链路。代码取自 `MyThird/Source/MyThird/Public/PlayerCharacter.h` 与 `Private/PlayerCharacter.cpp`。

## 整体链路总览

先看全貌，再逐步展开。增强输入系统分三层，加上响应后的两条执行链：

```
鼠标键盘 → IMC（按键 → IA 映射表，编辑器里建资产）
              ↓ BeginPlay: AddMappingContext 注册
          IA（输入操作，如 IA_Move / IA_Look）
              ↓ SetupPlayerInputComponent: BindAction 绑定
          响应函数（C++ 普通成员函数）
              ├─ Move → AddMovementInput → CharacterMovementComponent 每帧消费 → 位移
              └─ Look  → AddControllerYaw/PitchInput → ControlRotation
                            → SpringArm(bUsePawnControlRotation) 跟随 → 相机旋转
```

| 层     | 内容                     | 在哪做                   |
| ------ | ------------------------ | ------------------------ |
| 资产层 | IA / IMC 资产            | 编辑器创建，C++ 只放引用 |
| 绑定层 | 注册 IMC、绑定 IA → 函数 | C++（本章）              |
| 响应层 | Move / Look 的具体逻辑   | C++（本章）              |

## 第一步：头文件声明

`PlayerCharacter.h` 中与输入、相机相关的声明：

```cpp
#include "InputActionValue.h"
#include "InputMappingContext.h"
#include "InputAction.h"

class USpringArmComponent;   // 前置声明，避免头文件堆 include
class UCameraComponent;

UCLASS()
class MYTHIRD_API APlayerCharacter : public ACharacter
{
    GENERATED_BODY()

protected:
    // 输入响应函数：普通成员函数即可当回调，不需要宏
    void Look(const FInputActionValue& Value);
    void Move(const FInputActionValue& Value);

private:
    UPROPERTY(EditAnywhere, BlueprintReadOnly, Category = Camera, meta = (AllowPrivateAccess = "true"))
    TObjectPtr<USpringArmComponent> CameraBoom;

    UPROPERTY(EditAnywhere, BlueprintReadOnly, Category = Camera, meta = (AllowPrivateAccess = "true"))
    TObjectPtr<UCameraComponent> PlayerCamera;

    // Input
    UPROPERTY(EditDefaultsOnly, Category = "Input")
    TObjectPtr<UInputMappingContext> DefaultMappingContext;

    UPROPERTY(EditDefaultsOnly, Category = "Input")
    TObjectPtr<UInputAction> MoveAction;

    UPROPERTY(EditDefaultsOnly, Category = "Input")
    TObjectPtr<UInputAction> LookAction;
};
```

要点：

- private 成员要暴露给编辑器，必须带 `meta = (AllowPrivateAccess = "true")`（详见[第 4 章](/C++/4.常用宏与反射.md)）；
- 这里输入资产用的 `EditDefaultsOnly`——只允许在 **类默认值（CDO / 蓝图子类的类默认值）** 上编辑，场景里每个实例不可单独改。模板用的是 `EditAnywhere`。输入映射这种全局一致的东西，`EditDefaultsOnly` 语义上更严格，两种都常见；
- IA / IMC 资产还是编辑器里建的那套（`IMC_Default`、`IA_Move`、`IA_Look`），在蓝图子类的细节面板里拖进去——C++ 不写死资源路径。

## 第二步：构造函数——搭相机 + 三步旋转配置

这是第三人称手感的**核心**，代码里用 1/2/3 注释标出了三步：

```cpp
APlayerCharacter::APlayerCharacter()
{
    PrimaryActorTick.bCanEverTick = true;

    // SpringArm（相机摇臂）：挂在胶囊体上，末端拖一台相机
    CameraBoom = CreateDefaultSubobject<USpringArmComponent>(TEXT("CameraBoom"));
    CameraBoom->SetupAttachment(RootComponent);
    CameraBoom->TargetArmLength = 600.0f;   // 相机离角色的距离

    // 1.不要让角色随着控制器旋转
    // 身体不直接跟随控制器旋转，由移动组件朝移动方向转身
    bUseControllerRotationYaw = false;
    bUseControllerRotationRoll = false;
    bUseControllerRotationPitch = false;

    // 2.相机杆旋转，而相机不旋转
    // Boom 跟随控制器旋转，Look 输入才能带动相机俯仰/旋转
    CameraBoom->bUsePawnControlRotation = true;
    PlayerCamera->bUsePawnControlRotation = false;

    // 3.角色要根据其运动方向进行旋转
    GetCharacterMovement()->bOrientRotationToMovement = true;
    GetCharacterMovement()->RotationRate = FRotator(0.f, 400.f, 0.f);

    // 相机挂在 Boom 末端（SocketName 是 SpringArm 自带的末端插槽）
    PlayerCamera = CreateDefaultSubobject<UCameraComponent>(TEXT("PlayerCamera"));
    PlayerCamera->SetupAttachment(CameraBoom, USpringArmComponent::SocketName);
}
```

> 注意：实际工程里 `PlayerCamera` 的创建在 1/2/3 注释**之前**——上面为了讲解把相机创建挪到了前面。抄代码时以仓库里的 `.cpp` 为准。

三步各自解决什么问题：

### ① 身体不跟控制器转

`bUseControllerRotationPitch / Yaw / Roll` 决定**角色胶囊体**是否直接跟随 ControlRotation。三个默认就是 `false`（`APawn` 构造函数里定的），显式写出来是官方模板的写法——表明"这里故意关掉"。尤其**千万别开 Pitch**：整个胶囊体会跟着相机俯仰翻跟头。

### ② Boom 跟控制器转（相机能上下看的关键）

`bUsePawnControlRotation = true` 让 SpringArm **每帧把自己的旋转设为 ControlRotation**。没有这一步，`AddControllerPitchInput` 改了 ControlRotation 也没人理，相机纹丝不动。

两个连带影响：

- 开启后 Boom 的旋转完全被 ControlRotation 接管，之前 `SetRelativeRotation(FRotator(-40.f, 0.f, 0.f))` 这种固定俯角**会被覆盖**，开局是平视、随鼠标变化；
- 相机自己不读控制旋转（`false`），它的旋转是**挂在 Boom 末端继承来的**——Boom 转相机自然跟着转，不需要（也不应该）再给相机单独开。

### ③ 身体朝移动方向转身

`bOrientRotationToMovement = true` + `RotationRate`：移动时角色平滑转身面向移动方向（400°/s）。没有这步，角色会保持初始朝向"横着滑行"。俯仰限制不用操心，`PlayerCameraManager` 默认的 PitchMin/Max（约 ±89.9°）会兜底。

**分工总结：相机跟 Controller 转，身体跟移动方向转，互不干扰。**

## 第三步：BeginPlay 注册 IMC

```cpp
void APlayerCharacter::BeginPlay()
{
    Super::BeginPlay();

    const ULocalPlayer* Player = (GEngine && GetWorld()) ? GEngine->GetFirstGamePlayer(GetWorld()) : nullptr;
    if (Player)
    {
        UEnhancedInputLocalPlayerSubsystem* SubSystem =
            ULocalPlayer::GetSubsystem<UEnhancedInputLocalPlayerSubsystem>(Player);
        if (DefaultMappingContext)
        {
            SubSystem->AddMappingContext(DefaultMappingContext, 0);   // 0 = 优先级
        }
    }
}
```

获取子系统的链路固定：**LocalPlayer → GetSubsystem&lt;UEnhancedInputLocalPlayerSubsystem&gt;()**。这里取 LocalPlayer 的方式和[第 2 章](/C++/2.增强输入系统的C++绑定.md)（`Cast<APlayerController>(GetController())->GetLocalPlayer()`）不同但殊途同归——单机单玩家时 `GetFirstGamePlayer` 就够用。IMC 不注册，后面 BindAction 绑得再对也没输入进来。

## 第四步：SetupPlayerInputComponent 绑定

```cpp
void APlayerCharacter::SetupPlayerInputComponent(UInputComponent* PlayerInputComponent)
{
    Super::SetupPlayerInputComponent(PlayerInputComponent);

    UEnhancedInputComponent* EnhancedInputComponent = CastChecked<UEnhancedInputComponent>(PlayerInputComponent);
    if (EnhancedInputComponent)
    {
        EnhancedInputComponent->BindAction(MoveAction, ETriggerEvent::Triggered, this, &APlayerCharacter::Move);
        EnhancedInputComponent->BindAction(LookAction, ETriggerEvent::Triggered, this, &APlayerCharacter::Look);
    }
}
```

- `SetupPlayerInputComponent` 是 Pawn 初始化输入时引擎自动调用的**标准绑定位置**，时机早于 BeginPlay；
- `CastChecked`：转换失败直接断言崩溃（开发期暴露问题），比静默失败的 `Cast` 更适合这里——启用增强输入的项目里 PlayerInputComponent 必然是 `UEnhancedInputComponent`；
- 移动/视角用 `Triggered`（持续触发），跳跃这类瞬时动作用 `Started` / `Completed`——`ETriggerEvent` 全表见[第 2 章](/C++/2.增强输入系统的C++绑定.md)。

## 第五步：Move 的两种写法（本章重点）

### 写法一：基于角色自身朝向（被注释掉的版本）

```cpp
AddMovementInput(GetActorForwardVector(), MovementVector.X);
AddMovementInput(GetActorRightVector(), MovementVector.Y);
```

方向取自**角色胶囊体的朝向**。问题：第三人称里相机自由旋转、身体朝移动方向转，两者经常不同步——相机转到侧面后按 W，角色沿**身体朝向**走而不是**屏幕前方**，操作感拧巴。

### 写法二：基于 Controller（相机）朝向（启用版本）

```cpp
void APlayerCharacter::Move(const FInputActionValue& Value)
{
    // 输入值是 Vector2D：X = 前后，Y = 左右
    const FVector2D MovementVector = Value.Get<FVector2D>();

    if (Controller != nullptr)
    {
        const FRotator Rotation = Controller->GetControlRotation();
        // 只留 Yaw，把 Pitch/Roll 清零
        const FRotator YawRotation(0, Rotation.Yaw, 0);
        const FVector ForwardDirection = FRotationMatrix(YawRotation).GetUnitAxis(EAxis::X);
        const FVector RightDirection   = FRotationMatrix(YawRotation).GetUnitAxis(EAxis::Y);
        AddMovementInput(ForwardDirection, MovementVector.X);
        AddMovementInput(RightDirection, MovementVector.Y);
    }
}
```

方向取自**ControlRotation 的 Yaw**（即玩家视角的水平朝向），WASD 始终贴合屏幕方向——第三人称标准手感。

|          | 写法一                                                 | 写法二                                            |
| -------- | ------------------------------------------------------ | ------------------------------------------------- |
| 参考方向 | 角色身体朝向                                           | 相机/视角朝向                                     |
| 手感     | 相机一转就与移动方向脱节                               | WASD 始终贴合屏幕（主流第三人称）                 |
| 适用     | 第一人称，或 `bUseControllerRotationYaw = true` 的角色 | 第三人称 + 自由相机 + `bOrientRotationToMovement` |

> **为什么必须拆出 YawRotation？** ControlRotation 带俯仰（第三人称 Boom 通常还带 -40° 左右的固定俯角）。直接用完整旋转取前向量，低头时"前方"会斜指向地下。只留 Yaw 保证移动方向**水平**。

## 第六步：Look 与相机控制链路

```cpp
void APlayerCharacter::Look(const FInputActionValue& Value)
{
    const FVector2D LookAxisVector = Value.Get<FVector2D>();

    if (Controller != nullptr)
    {
        // Y 轴控制左右视角，X 轴（鼠标 deltaY）控制俯仰
        AddControllerYawInput(LookAxisVector.X);
        AddControllerPitchInput(LookAxisVector.Y);
    }
}
```

`Look` 本身只做一件事：把输入累加进 Controller 的 ControlRotation。真正让画面动起来的是第二步埋下的链路：

```
AddControllerPitchInput → ControlRotation.Pitch 变化
    → SpringArm（bUsePawnControlRotation = true）每帧跟随
    → 相机（挂在 Boom 末端）跟着俯仰 / 旋转
```

另外 SpringArm 默认开着碰撞检测（`bDoCollisionTest`）：俯仰到贴近地面、相机即将穿墙时，Boom 会自动缩短拉近——免费获得防穿墙。

## 常见问题排查

| 症状                        | 检查                                                                                              |
| --------------------------- | ------------------------------------------------------------------------------------------------- |
| 鼠标上下没反应（Look 失效） | CameraBoom 的 `bUsePawnControlRotation` 是否为 true                                               |
| 移动方向和屏幕拧着          | Move 里是否用了写法一（`GetActorForwardVector`）                                                  |
| 角色翻跟头 / 侧躺           | 是不是把 `bUseControllerRotationPitch / Roll` 开了                                                |
| 角色横着滑行不转身          | `bOrientRotationToMovement` 没开，或 `RotationRate` 为 0                                          |
| 相机开局俯角不对            | `bUsePawnControlRotation = true` 时 `SetRelativeRotation` 的俯角会被 ControlRotation 覆盖，属正常 |
| 蓝图子类行为不对            | 蓝图细节面板里同名属性的设置会**覆盖** C++ 默认值，两边要一致                                     |
| 完全没输入                  | IMC 是否 Add 成功、蓝图子类里 IA / IMC 资产是否拖了                                               |

## 小结

- 三步旋转配置是第三人称的骨架：**身体不跟控制器 → Boom 跟控制器 → 身体朝移动方向转身**；
- `bUsePawnControlRotation` 是"相机能不能上下看"的开关，开了之后固定俯角失效属正常；
- Move 用 **ControlRotation 的 Yaw** 算前/右方向（且必须清掉 Pitch），不要用角色身体朝向；
- Look 只改 ControlRotation，画面旋转由 SpringArm 链路完成；
