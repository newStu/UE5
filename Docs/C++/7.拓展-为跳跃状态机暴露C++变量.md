# 拓展：为跳跃状态机暴露 C++ 变量（IsFalling / VerticalVelocity）

> **定位：拓展思路，当前工程尚未实践。** 本篇 C++ 工程暂时只绑定了移动（`Speed` 驱动 Idle ↔ Run 混合），**还没有绑定跳跃功能**。这里预先把"将来给跳跃状态机补变量"的完整思路整理出来，作为后续实践时的参考——原文档[第 6 章](/C++/6.动画类的C++实现与蓝图状态机绑定.md)只讲已落地的 C++ 编程过程，本章是它的前瞻延伸。

## 为什么要额外暴露变量

[第 6 章](/C++/6.动画类的C++实现与蓝图状态机绑定.md)的 `Speed` 用 `VSizeXY` 计算水平速度，**刻意过滤掉了 Z 轴**——这是地面移动混合的正确做法，但也意味着：跳跃状态机的转换条件（起跳？下落？落地？）从 `Speed` 里拿不到任何信息。

蓝图篇[角色跳跃](/蓝图/4.角色跳跃/角色跳跃.md)一章的做法，是在转换规则里现场拆 `Velocity.Z`。C++ 版更彻底：把跳跃判断需要的值也变成 `UPlayerAnim` 的成员，状态机里只剩"变量 → 条件"一根线的连接工作。

两个互补的变量：

| 变量              | 来源                              | 语义                                       |
| ----------------- | --------------------------------- | ------------------------------------------ |
| `IsFalling`       | `MovementComponent->IsFalling()`  | 腾空标志：跳跃上升/下落均为 true，落地 false |
| `VerticalVelocity`| `MovementComponent->Velocity.Z`   | 垂直速度：> 0 上升，< 0 下落               |

## C++ 侧改动（拓展代码，暂未合入工程）

在 `PlayerAnim.h` 的 `Speed` 之后追加两个成员：

```cpp
/** 角色是否腾空(跳跃上升/下落均为 true,在地面为 false),供状态机切换跳跃相关状态 */
UPROPERTY(BlueprintReadOnly, Category="CPlus")
bool IsFalling = false;

/** 垂直方向(Z 轴)速度:> 0 上升、< 0 下落,起跳判断配合阈值使用(如 > 100) */
UPROPERTY(BlueprintReadOnly, Category="CPlus")
float VerticalVelocity = 0.f;
```

在 `NativeUpdateAnimation` 的判空块内追加两行：

```cpp
if (PlayerCharacterMovement)
{
    Speed = UKismetMathLibrary::VSizeXY(PlayerCharacterMovement->Velocity);

    // 腾空状态与垂直速度:Speed 被过滤掉了 Z 轴,跳跃判断用这两个值
    IsFalling = PlayerCharacterMovement->IsFalling();
    VerticalVelocity = PlayerCharacterMovement->Velocity.Z;
}
```

三个变量各司其职：**`Speed` 管地面移动混合，`IsFalling` / `VerticalVelocity` 管腾空状态切换**。全部标 `BlueprintReadOnly`，与第 6 章的暴露通道一致。

> 前置条件：跳跃本身还得先绑上——`APlayerCharacter` 里加 `JumpAction` 的 `BindAction`（`Started` 时 `Jump()`、`Completed` 时 `StopJumping()`），输入绑定的做法见[第 2 章](/C++/2.增强输入系统的C++绑定.md)、[第 5 章](/C++/5.输入控制与第三人称相机.md)。

## 蓝图侧：状态机跳跃转换

改完 C++ 重启编辑器后，AnimBP 变量面板会多出 `IsFalling` / `VerticalVelocity` 两个只读变量。状态机结构参照蓝图篇[角色跳跃](/蓝图/4.角色跳跃/角色跳跃.md)，转换条件也直接沿用它 debug 验证过的版本：

```
Locomotion ──(VerticalVelocity > 100 且 IsFalling)──→ Jump_Start ──(起跳动画剩余 ≤ 0.1s)──→ Jump_Loop
     ↑                                                                                  │ NOT IsFalling(落地)
     └──(Speed ≥ 1 或 VerticalVelocity ≥ 1 或落地动画剩余 ≤ 0.1s)────────── Jump_End ←──┘
```

| 转换                    | 条件写法                                                     | 说明                 |
| ----------------------- | ------------------------------------------------------------ | -------------------- |
| Locomotion → Jump_Start | `VerticalVelocity > 100` **AND** `IsFalling`                 | 向上速度够大**且**已离地才切；阈值 100 过滤微小垂直速度抖动，防误触发 |
| Jump_Start → Jump_Loop  | 起跳动画剩余时间 `≤ 0.1s`（`Get Relevant Anim Time Remaining` 节点；或勾选转换规则的 Automatic Rule Based on Sequence Player in State） | 起跳动作快播完才切入空中循环，衔接自然。**注意：条件留空的过渡永远不会触发** |
| Jump_Loop → Jump_End    | **NOT** `IsFalling`（落地）                                  | Jump_End 是**落地动作**：整个腾空期（上升 + 下落）都由 Jump_Loop 循环覆盖，落地瞬间才切 |
| Jump_End → Locomotion   | `Speed ≥ 1` **OR** `VerticalVelocity ≥ 1` **OR** 落地动画剩余 `≤ 0.1s` | 开始移动 / 再次起跳 / 落地动画播完，任一满足即返回；三个条件各防一种卡死（见下） |

这套条件不是新发明，是[蓝图篇角色跳跃](/蓝图/4.角色跳跃/角色跳跃.md)经 PIE debug 修出来的验证版本：起跳加阈值防抖动、切换看动画剩余时间保证动作播到位、`Jump_End → Locomotion` 用三条件 OR 兜底——蓝图篇 9.2 节曾因只写 `Speed >= 1` 导致"原地起跳卡死在 Jump_End"，迁移到 C++ 变量时**别把条件简化成单条**。

对比蓝图篇：转换规则里不再需要 `TryGetPawnOwner → Velocity → 拆分向量 → Z` 那串节点，**判断要的 Z、移动要的 Speed，都由同一份 C++ 缓存的移动组件每帧算好**；各状态挂的动画资产与蓝图篇相同（`Jump_Start` 用 `MM_Jump`、`Jump_Loop` 用 `MM_Fall_Loop` 这类），Sequence Player 节点若显示**绿色（无效）**，先查细节面板的 Additive Animation Type 是否设错——这两处的操作细节见蓝图篇对应小节。

## 常见问题排查

| 症状                     | 检查                                                                                     |
| ------------------------ | ---------------------------------------------------------------------------------------- |
| 永远进不了跳跃状态       | 角色根本没跳（跳跃输入未绑定）；或 `IsFalling` 没刷新（编辑器开着时改了 C++ 没重启）      |
| 跳跃时动画抽搐、切进跑步 | 转换条件误用了 `Speed`（它含不了 Z）；跳跃判断应使用 `IsFalling` / `VerticalVelocity`    |
| 卡在 Jump_Start 不往下切 | 过渡条件留空了——空条件**永远不会触发**，用剩余时间 `≤ 0.1s` 或勾选 Automatic Rule        |
| 落地动画一帧都不播就切走 | `Jump_End → Locomotion` 只写了 `IsFalling == false`——它落地瞬间即真，需 OR 上剩余时间兜底 |
| 落地后卡在 Jump_End      | `Jump_End → Locomotion` 的三个 OR 条件是否齐全——只写 `Speed ≥ 1` 会复现蓝图篇"原地起跳卡死"的 bug |

## 小结

- `Speed` 刻意过滤 Z 轴，跳跃判断因此需要独立的 `IsFalling` / `VerticalVelocity`；
- 两者都从第 6 章缓存的 `PlayerCharacterMovement` 里来，蓝图状态机里只剩"变量 → 条件"的连接；
- 转换条件沿用蓝图篇 debug 验证过的组合：起跳加阈值、切换看剩余时间、返回用三条件 OR 兜底——**别简化成单条件**；
